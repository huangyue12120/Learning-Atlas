# 视觉 Transformer 与图像块词元原语

> 在进入任何多模态模型之前，图像必须先变成 Transformer 能够处理的词元序列。2020 年的 ViT 论文用 16x16 像素图像块、线性投影和位置嵌入回答了这个问题。五年后的 2026 年，所有前沿模型（原生 2576px 的 Claude Opus 4.7、Gemini 3.1 Pro、Qwen3.5-Omni）仍然从这里开始——编码器从 ViT 变成了 DINOv2 和 SigLIP 2，加入了寄存器词元，位置方案变成了 2D-RoPE，但这个原语没有改变。本课端到端梳理图像块词元流水线，并用标准库 Python 实现它，让 Phase 12 后续课程对“视觉词元”有一个具体的心智模型。

**类型：** 学习
**语言：** Python（标准库，图像块分词器 + 几何计算器）
**前置课程：** Phase 7（Transformer）、Phase 4（计算机视觉）
**预计时间：** 约 120 分钟

## 学习目标

- 将形状为 HxWx3 的图像转换为带有正确位置编码的图像块词元序列。
- 为给定的（图像块大小、分辨率、隐藏维度、深度）计算 ViT 的序列长度、参数量和 FLOPs。
- 说出 ViT 从 2020 年研究原型走向 2026 年生产系统的三个升级：自监督预训练（DINO / MAE）、寄存器词元和原生分辨率打包。
- 针对下游任务，在 CLS 池化、平均池化和寄存器词元之间做出选择。

## 问题

Transformer 处理的是向量序列。文本本来就是序列（字节或词元），而图像是带有三个颜色通道的二维像素网格，并不是序列。如果把每个像素都展平，一张 224x224 的 RGB 图像会变成 150,528 个词元，而这个长度下的自注意力（序列长度的平方复杂度）根本无法运行。

2020 年以前的做法是在前端接一个 CNN 特征提取器：ResNet 生成一个由 2048 维向量组成的 7x7 特征图，再把这 49 个向量作为词元送入 Transformer。这种方法有效，但继承了 CNN 的偏置（平移等变性、局部感受野），也失去了 Transformer 对规模扩展的适应性。

Dosovitskiy 等人（2020）提出了一个直截了当的问题：如果跳过 CNN 呢？把图像切成固定大小的图像块（例如 16x16 像素），将每个图像块线性投影为一个向量，加上位置嵌入，再把序列送入原生 Transformer。当时这近乎离经叛道——视觉模型不使用卷积。随着数据量足够大（先是 JFT-300M，后来是 LAION），它在 ImageNet 上超过了 ResNet，并且还在持续提升。

到 2026 年，ViT 原语已经成为毫无争议的基础。每个开放权重 VLM 的视觉塔都是它的某种后代（DINOv2、SigLIP 2、CLIP、EVA、InternViT）。现在的问题不再是“是否应该使用图像块”，而是“图像块多大、分辨率如何安排、采用什么预训练目标、使用哪种位置编码”。

## 概念

### 将图像块作为词元

给定形状为 `(H, W, 3)` 的图像 `x` 和图像块大小 `P`，把图像切成 `(H/P) x (W/P)` 个不重叠图像块组成的网格。每个图像块是一个 `P x P x 3` 的像素立方体。把每个立方体展平为 `3 P^2` 维向量，再使用形状为 `(3 P^2, D)` 的共享线性投影 `W_E`，将每个图像块映射到模型隐藏维度 `D`。

ViT-B/16 的经典配置如下：
- 分辨率 224、图像块大小 16 → 14x14 网格 → 196 个图像块词元。
- 每个图像块包含 `16 x 16 x 3 = 768` 个像素值，投影到 `D = 768`。
- 加入一个可学习的 `[CLS]` 词元 → 序列长度为 197。

图像块投影在数学上等同于一个卷积核大小为 `P`、步幅为 `P`、输出通道为 `D` 的二维卷积。这正是生产代码的实际实现方式——`nn.Conv2d(3, D, kernel_size=P, stride=P)`。“线性投影”是概念上的表述；卷积核实现更高效。

### 位置嵌入

图像块没有内在顺序——Transformer 看到的只是一个袋子。早期 ViT 加入了可学习的一维位置嵌入（每个位置一个 768 维向量，共 197 个）。这种方法有效，但把模型绑定到了训练分辨率：推理时如果改变网格，就必须对位置表做插值。

现代视觉骨干使用 2D-RoPE（Qwen2-VL 的 M-RoPE、SigLIP 2 的默认方案）或因子化二维位置。2D-RoPE 根据图像块的（行、列）索引旋转 query 和 key 向量，使模型能从旋转角度推断二维相对位置。它不需要位置表，模型在推理时也能处理任意网格大小。

### CLS 词元、池化输出与寄存器词元

图像级表示应该是什么？有三种选择并存：

1. `[CLS]` 词元。将一个可学习向量置于图像块序列开头。经过所有 Transformer 块后，CLS 词元的隐藏状态就是图像表示。它继承自 BERT，由原始 ViT 和 CLIP 使用。
2. 平均池化。对图像块词元输出的隐藏状态求平均。SigLIP、DINOv2 和大多数现代 VLM 都使用它。
3. 寄存器词元。Darcet 等人（2023）观察到，没有显式汇聚词元的 ViT 会形成高范数的“伪影”图像块，劫持自注意力。加入 4–16 个可学习寄存器词元可以吸收这部分负荷，并提升稠密预测质量（分割、深度）。DINOv2 和 SigLIP 2 都内置了寄存器。

这个选择会影响下游任务。CLS 适合分类。对于把图像块词元送入 LLM 的 VLM，则完全跳过池化——每个图像块都变成一个 LLM 输入词元。寄存器在交接前会被丢弃（它们是脚手架，不是内容）。

### 预训练：监督、对比、掩码与自蒸馏

2020 年的 ViT 在 JFT-300M 上以监督分类方式预训练。它很快被以下方案取代：

- CLIP（2021）：在 4 亿个图文对上做图文对比学习。见第 12 阶段第 02 课。
- MAE（2021，He 等）：掩盖 75% 的图像块，重建像素。它是自监督的，只需要纯图像。
- DINO（2021）/ DINOv2（2023）：使用学生—教师结构做自蒸馏，不需要标签或标题。2023 年的 DINOv2 ViT-g/14 是最强的纯视觉骨干，也是“稠密特征”使用场景的默认选择。
- SigLIP / SigLIP 2（2023、2025）：使用 sigmoid 损失的 CLIP，并通过 NaFlex 支持原生宽高比。它是 2026 年开放 VLM 的主流视觉塔（Qwen、Idefics2、LLaVA-OneVision）。

预训练方式决定了骨干擅长什么：CLIP/SigLIP 适合与文本做语义匹配，DINOv2 适合稠密视觉特征，MAE 适合作为下游微调的起点。

### 缩放定律

ViT 的缩放研究（Zhai 等，2022）表明，ViT 的质量会遵循关于模型规模、数据规模和算力的可预测规律。在算力固定时：
- 更大的模型 + 更多数据 → 更好的质量。
- 图像块大小是序列长度与保真度之间的控制杆。图像块 14（DINOv2/SigLIP SO400m 的典型选择）比图像块 16 为每张图像提供更多词元；它更适合 OCR 和稠密任务，但速度更慢。
- 分辨率是另一个重要控制杆。从 224 提升到 384 再到 512 几乎总会带来收益，但 FLOPs 的代价是二次增长。

ViT-g/14（10 亿参数，图像块 14，分辨率 224 → 256 个词元）和 SigLIP SO400m/14（4 亿参数，图像块 14）是 2026 年开放 VLM 的两种主力编码器。

### ViT 的参数量

完整计算在 `code/main.py` 中。对于 224 分辨率的 ViT-B/16：

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

在加载检查点之前，可以用这种方式粗略估算任意 ViT。骨干大小决定了下游 VLM 的显存下限。

### 2026 年生产配置

2026 年大多数开放 VLM 使用的编码器是原生分辨率（NaFlex）的 SigLIP 2 SO400m/14。它具有：
- 4 亿个参数。
- 图像块大小 14，默认分辨率 384 → 每张图像 729 个图像块词元。
- 图像级任务使用平均池化；做 VQA 时，全部 729 个图像块都会流入 LLM。
- 4 个寄存器词元，在交接给 LLM 前丢弃。
- 使用图像级缩放的 2D-RoPE，以支持原生宽高比。

## 使用它

`code/main.py` 是一个图像块分词器和几何计算器。它接收（图像 H、W、图像块 P、隐藏维度 D、深度 L），并报告：

- 图像切块后的网格形状和序列长度。
- 合成的 8x8 像素玩具图像的词元序列（逐步走过展平 + 投影路径）。
- 按图像块嵌入、位置嵌入、Transformer 块和输出头拆分的参数量。
- 目标分辨率下一次前向传播的 FLOPs。
- ViT-B/16 @ 224、ViT-L/14 @ 336、DINOv2 ViT-g/14 @ 224、SigLIP SO400m/14 @ 384 的对比表。

运行它，并把参数量与已发布的数字对照。调整图像块大小和分辨率，直观感受词元数量的代价。

## 交付成果

本课生成 `outputs/skill-patch-geometry-reader.md`。给定一个 ViT 配置（图像块大小、分辨率、隐藏维度、深度），它会给出词元数量、参数量和显存估计，并说明理由。每当你为 VLM 选择视觉骨干时，都可以使用这个技能——它能避免“词元爆炸，把我的 LLM 上下文填满了”的意外。

## 练习

1. 计算 Qwen2.5-VL 在原生 1280x720 输入、图像块大小为 14 时的图像块词元序列长度。它与只有 CLS 的表示相比如何？

2. 一帧 1080p 图像（1920x1080）使用图像块 14 时会产生多少个词元？以 30 FPS 处理 5 分钟视频时，总共有多少视觉词元？在池化、帧抽样和词元合并中，哪一项最能节省成本？

3. 用纯 Python 实现图像块词元的平均池化。验证 DINOv2 输出的 196 个词元做平均池化后，与调用模型 `forward` 获取池化嵌入时返回的结果一致。

4. 阅读《Vision Transformers Need Registers》（arXiv:2309.16588）的第 3 节。用两句话说明寄存器吸收了什么伪影，以及这为什么对下游稠密预测很重要。

5. 修改 `code/main.py` 以支持 patch-n'-pack：给定一个不同分辨率图像组成的列表，生成一个打包后的序列和块对角注意力掩码。到达第 12.06 课时与其对照验证。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| 图像块（Patch） | “16x16 像素方块” | 输入图像中固定大小的不重叠区域；每个区域变成一个词元 |
| 图像块嵌入 | “线性投影” | 将展平的图像块像素映射为 D 维向量的共享学习矩阵（或步幅为 P 的 Conv2d） |
| CLS 词元 | “类别词元” | 置于序列开头、最终隐藏状态表示整张图像的可学习向量；2026 年可选 |
| 寄存器词元 | “汇聚词元” | 吸收 ViT 在预训练期间形成的高范数注意力伪影的额外可学习词元 |
| 位置嵌入 | “位置信息” | 让序列感知顺序的逐位置向量或旋转；2D-RoPE 是现代默认方案 |
| 网格 | “图像块网格” | 对给定分辨率和图像块大小而言，形状为 `(H/P) x (W/P)` 的二维图像块数组 |
| NaFlex | “原生灵活分辨率” | SigLIP 2 的特性：单个模型无需重新训练即可服务多个宽高比和分辨率 |
| 骨干 | “视觉塔” | 预训练图像编码器，其图像块词元输出会送入 VLM 的 LLM |
| 池化 | “图像级摘要” | 将图像块词元变成一个向量的策略：CLS、平均、注意力或基于寄存器 |
| 图像块 14 对比 16 | “更细与更粗的网格” | 图像块 14 每张图像产生更多词元，对 OCR 保真度更好但更慢；图像块 16 是经典默认值 |
