# LLaVA-OneVision：一个模型统一单图像、多图像与视频

> 在 LLaVA-OneVision（Li 等，2024 年 8 月）之前，开放 VLM 世界有相互分离的谱系：用于单图像的 LLaVA-1.5、Mantis 和 VILA 这样的多图像模型，以及 Video-LLaVA 和 Video-LLaMA 这样的视频模型。每个模型都在自己的基准上胜出，却在其他基准上失败。LLaVA-OneVision 认为，一套课程可以训练一个模型统治三种场景，而且由此产生的任务迁移效应（单图像技能迁移到视频，多图像推理迁移到单图像）胜过专家模型能力的简单相加。这套方案看似简单：在不同场景之间保持不变的视觉词元预算，再加上从单图像到 OneVision（多图像）再到视频的明确课程。本课阅读这套预算、课程和涌现行为。

**类型：** 构建
**语言：** Python（标准库，词元预算求解器 + 课程规划器）
**前置课程：** Phase 12 · 05（LLaVA）、Phase 12 · 06（任意分辨率）
**预计时间：** 约 180 分钟

## 学习目标

- 设计一个在单图像、多图像和视频输入之间保持不变的视觉词元预算。
- 安排训练课程，使技能从单图像迁移到视频，同时避免灾难性遗忘。
- 解释在课程安排正确时，为什么同样参数量的一个模型会超过专家模型。
- 说出 LLaVA-OneVision 报告的三个涌现能力：多摄像头推理、标记集合提示、iPhone 截图智能体。

## 问题

单图像、多图像和视频对模型的压力各不相同。

单图像需要高分辨率词元（AnyRes，约 2880 个视觉词元）以捕捉 OCR 和精细细节。每个样本的预算是一张图像、2880 个词元。

多图像希望每张图像使用中等分辨率（每张约 576 个词元），让多图像推理能放入上下文。每个样本的预算是 4–8 张图像、每张 576 个词元，共 2300–4600 个词元。

视频希望用低分辨率处理更多帧（池化后每帧约 196 个词元），以捕捉时间动态。每个样本的预算是 8–32 帧、每帧 196 个词元，共 1600–6200 个词元。

如果训练多个独立模型，你可以为每个模型选择一个预算。如果训练一个模型，就需要让预算在不同场景间合理缩放，同时不能撑爆上下文。

OneVision 之前的默认答案是“训练一个场景，忽略其他场景”。Video-LLaVA 在图像模型上追加训练阶段来适配视频。LLaVA-NeXT 通过平铺增加多图像支持。没有一个方案能干净地处理三者。

## 概念

### OneVision 词元预算

LLaVA-OneVision 选择一个约 3000–4000 个词元的统一视觉预算，再按场景进行分配：

- 单图像：AnyRes-9（3x3 图块 + 缩略图），每个图块在 384 分辨率下有 729 个图像块，使用激进的 2x2 双线性池化 → 每个图块 182 个词元。总计：9 * 182 + 182 = 1820 个词元。或者使用每个图块 729 个词元的 AnyRes-4：2916 + 729。
- 多图像：每张图像使用中等分辨率（384、不平铺），每张 729 个词元、不池化。预算 6 张图像 → 4374 个词元。
- 视频：32 帧、384 分辨率，使用激进的 3x3 双线性池化 → 每帧 81 个词元。总计：32 * 81 = 2592 个词元。

这种分配让总词元大致保持不变。LLM 不会看到撑爆上下文的批量。编码器在每种场景产生不同的几何形状，但 LLM 消费相同的预算。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图像 SFT（阶段 SI）。所有数据都是单图像 + 文本。使用高分辨率 AnyRes 输入训练，教会模型感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据以及 OneVision 特有的单图像数据。
2. OneVision SFT（阶段 OV）。混合单图像 + 多图像 + 视频（均匀抽取帧）。使用统一词元预算训练，教会模型处理异构批量形状。不重置权重——从阶段 SI 继续训练。
3. 任务迁移（阶段 TT）。继续使用目标任务混合训练，通常根据产品需要偏重多图像或视频。部署前可以选择性微调。

关键在于课程顺序。先训练视频或多图像，即使数据相同，也会比先训练单图像产生更差的图像性能。论文明确做了这个消融。

### 课程为什么有效

单图像训练建立感知基础。图像块词元携带细粒度视觉特征，LLM 学会将它们与文本整合。多图像和视频引入结构性挑战（哪张图像是哪张、什么先发生），如果没有牢固的感知基础，这些挑战很难学习。

如果从头混合训练所有场景，模型会感知欠拟合（每个批量中单图像数据有限），结构过拟合（多图像 / 视频数据很多）。结果是：模型学会跨图像推理模式，却在视觉上很浅。

课程排序先从阶段 SI 获得感知能力，然后从阶段 OV 获得组合式/时间推理，而不会丢掉任何一方。

### 跨场景涌现技能

LLaVA-OneVision 论文报告了三个涌现能力：

1. 多摄像头推理。模型分别在多图像 + 视频上训练；推理时要求它理解多摄像头驾驶场景。即使训练中从未见过这种确切格式，模型也能正确整合多个视角。
2. 标记集合提示。用户用编号标记标注图像中的物体，模型需要推理“标记 3 相对于标记 7 在做什么”。训练中没有标记或标注；这种能力来自空间定位 + 多图像引用的组合。
3. iPhone 截图智能体。用户提供 iPhone 屏幕截图，并要求模型规划下一次点击。模型在 UI 截图、用户工作流视频和多图像前后对照对上训练，随后泛化到智能体使用场景。

这些不是直接训练的任务，而是从课程的组合结构中涌现的。

### 视觉词元池化

词元预算需要池化。OneVision 在二维图像块网格上使用双线性插值：24x24 = 576 个图像块变成 12x12 = 144 个（缩小 2 倍），或变成 8x8 = 64 个（缩小 3 倍）。池化在图像块网格空间中完成，而不是在词元空间中完成，以保留局部性。

每种场景的池化因子本身也是超参数。池化更少 = 词元更多 = 表示更丰富；池化更多 = 词元更少 = 能容纳更多帧/图像。

### LLaVA-OneVision-1.5

2025 年的后续版本（LLaVA-OneVision-1.5，arXiv 2509.23661）在训练数据、模型权重和代码上都是“完全开放”的。在一些基准上，它缩小了与专有模型的差距，并让这套方案民主化。课程相同，数据更多，基础 LLM 更好，没有架构变化。

### 与 Qwen2.5-VL 对比

Qwen2.5-VL（第 12.09 课）做出了不同选择。它使用 M-RoPE 和动态 FPS，而不是固定池化。它的预算随输入缩放——一分钟视频使用的词元比五秒视频多。LLaVA-OneVision 固定预算，并调整池化规模。两者都有效，代价是可配置性与可预测性之间的取舍。

## 使用它

`code/main.py` 是 OneVision 风格 VLM 的课程与预算规划器。给定每个样本的词元预算和目标场景混合（例如 40% 单图像、30% 多图像、30% 视频），它会：

- 为每种场景分配分辨率、池化因子和帧数。
- 检查每种场景是否都在共享预算内。
- 报告预期词元数量、LLM FLOPs，以及哪些场景的词元不足。
- 打印逐阶段训练计划。

使用它来规划 OneVision 微调，或检查 VLM 部署的每次请求成本。

## 交付成果

本课生成 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每个样本的预算，它会输出 AnyRes 因子、每帧池化、视频帧数和课程阶段权重。每当你训练或微调统一场景的 VLM 时，都可以使用这个技能。

## 练习

1. 你的产品支持 80% 单图像、10% 多图像（2–4 张图像）、10% 视频（8–16 帧）。设计词元预算。由于不需要重度多图像处理而节省的预算，你会把它放在哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一个课程很可能解锁、但论文没有报告的第四种涌现技能。

3. 调换课程顺序——先训练多图像，再训练单图像，最后视频。预测哪些基准会下降，以及原因。

4. 论文报告视频基准每个样本只使用 8 帧训练。这能泛化到推理时的 30 秒视频吗？首先会破坏什么——词元预算还是时间推理？

5. 将 24x24 图像块双线性池化到 12x12，相当于每个维度缩小 4 倍。用标准库 Python 实现池化，并验证每个 2x2 块的均值与双线性输出一致。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| OneVision 场景 | “单图像、多图像或视频” | 统一 VLM 处理的三种输入形状之一；三者之间预算保持不变 |
| 词元预算 | “每个样本有多少词元” | 每个训练/推理样本中 LLM 看到的视觉词元总数，通常为 3000–4000 |
| 课程 | “训练顺序” | 为了涌现迁移而选择的阶段顺序（单图像 → 多图像 → 视频） |
| 双线性池化 | “缩小词元” | 对二维图像块网格应用双线性插值，在保留局部性的同时减少词元数 |
| 涌现技能 | “没有训练，却能工作” | 推理时出现、没有对应训练数据的能力，来自课程组合 |
| AnyRes-k | “k 图块设置” | k 个固定分辨率子图块 + 一张缩略图，典型 k ∈ {4, 9} |
| 任务迁移 | “跨场景泛化” | 通过共享骨干，单图像上学习的技能可以应用于视频，反之亦然 |
