# 多模态智能体与计算机使用（毕业课）

> 2026 年的前沿产品是一个多模态智能体：读取屏幕截图、点击按钮、浏览 Web UI、填写表单，并端到端完成工作流。SeeClick 和 CogAgent（2024）证明了 GUI 定位原语。Ferret-UI 增加了移动端，ChartAgent 引入了图表视觉工具使用。VisualWebArena 和 AgentVista（2026）是前沿模型追逐的基准——即使 Gemini 3 Pro 和 Claude Opus 4.7，在 AgentVista 的困难任务上也只有约 30% 的得分。本毕业课汇总 Phase 12 的全部线索：感知（高分辨率 VLM）、推理（带工具使用的 LLM）、定位（坐标输出）、长时域记忆和评估。

**类型：** 毕业课
**语言：** Python（标准库，动作 schema + 智能体循环骨架）
**前置课程：** Phase 12 · 05（LLaVA）、Phase 12 · 09（Qwen-VL JSON）、Phase 14（智能体工程）
**预计时间：** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建 VLM 可以输出为 JSON 的 GUI 定位 schema（点击坐标、输入文本、滚动、拖动）。
- 比较纯屏幕截图智能体、无障碍树智能体和混合智能体。
- 在一个小型 VisualWebArena 切片上建立多模态智能体基准评估。

## 问题

一个预订网站工作流是：“帮我找 4 月 15 日去东京的航班，要靠过道的座位、价格低于 800 美元，然后订下来。”

多模态智能体需要：

1. 截取浏览器屏幕截图。
2. 将屏幕截图 + URL + 目标解析成计划。
3. 输出结构化动作：在 (x,y) 点击，在元素 E 输入“Tokyo”，向下滚动，选择（单选按钮）。
4. 对浏览器执行动作。
5. 观察新状态（下一张屏幕截图）。
6. 重复直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误会跨步骤累积，因此恢复机制很重要。

## 概念

### GUI 定位——原语

GUI 定位就是：给定屏幕截图和自然语言指令，输出要点击的（x, y）坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是第一个规模化的开放结果：在合成 + 真实 GUI 数据上微调 VLM，输出纯文本词元形式的坐标，效果很好。

CogAgent（arXiv:2312.08914）增加了 1120x1120 的高分辨率编码，用于密集 UI，网页导航得分约 84%。

Ferret-UI（arXiv:2404.05719）聚焦移动 UI，并与 iOS 无障碍数据整合。

输出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复：如果屏幕截图之间坐标发生漂移，语义提示可以让系统重新定位。

### 动作 schema

典型的动作 schema 有 6–10 种动作类型：

- `click`：（x, y）
- `type`：（text, x?, y?）
- `scroll`：（direction, amount）
- `drag`：（x0, y0, x1, y1）
- `select`：（option_index）
- `hover`：（x, y）
- `navigate`：（url）
- `wait`：（ms）
- `done`：（success, explanation）

智能体每一步输出一个动作。浏览器封装器执行动作，并返回新状态。

### 纯屏幕截图与无障碍树

两种输入模式：

- 纯屏幕截图：完整图像，没有结构信息。最通用，可用于任何应用。
- 无障碍树：结构化 DOM / iOS 无障碍信息。定位可靠得多，但前提是能获得这棵树。
- 混合：两者都用；无障碍树为原子动作提供可靠定位，屏幕截图提供语义上下文。

生产智能体在可能时使用混合模式。浏览器自动化（Selenium + 无障碍能力）总能获得这棵树；桌面应用有时可以。

### 长时域记忆

一个 20 步工作流会生成 20 张屏幕截图，VLM 的上下文很快就会填满。三种压缩策略：

- 摘要链：每 5 步总结发生过的事情，丢掉旧屏幕截图。
- 跳帧：保留第一张、最后一张和每第 3 张屏幕截图。
- 工具记录日志：执行动作，保留做过什么的文本日志，不重新查看旧屏幕截图。

Claude 的 computer-use API 使用日志模式。它更简单，也更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）为图表理解引入了视觉工具使用：裁剪、缩放、OCR 和外部检测。智能体可以输出“裁剪到区域 (100, 200, 300, 400)，然后调用 OCR”这样的工具调用。工具返回文本，VLM 继续推理。

这个模式可以泛化：标记集合提示、区域标注和外部检测工具都属于同一个“输出工具调用，接收结构化响应”的 schema。

### 2026 年的基准

- ScreenSpot-Pro：约 1k 张网页屏幕截图上的 GUI 定位。开放 SOTA Qwen2.5-VL-72B 约 85%，前沿模型约 90%。
- VisualWebArena：端到端网页任务（购物、论坛、分类信息）。开放 SOTA 约 20%，Gemini 3 Pro 约 27%。
- AgentVista（arXiv:2602.23166）：2026 年最难的基准。覆盖 12 个领域的真实工作流。前沿模型得分 27–40%，开放模型 10–20%。
- WebArena / WebShop：较早的基准，已被前沿模型饱和。

### 为什么仍然困难

智能体性能瓶颈：

1. 细粒度视觉定位。“点击小 X”在移动分辨率上经常失败。
2. 长时域规划。执行 10 个动作后，智能体会偏离目标。
3. 错误恢复。点击失败（点错按钮）时，检测和恢复很少出现在训练数据中。
4. 跨页面上下文。在标签页或长表单之间跳转会丢失状态。

研究方向包括：记忆架构、显式重新规划、多模态验证（用屏幕截图匹配来判断动作是否成功）。

### 毕业课构建

毕业任务是构建一个计算机使用智能体：

1. 读取预订网站模拟页面的 HTML + 屏幕截图。
2. 规划多步序列：搜索 → 选择 → 填表 → 提交。
3. 输出符合动作 schema 的 JSON 动作。
4. 在固定的 10 任务切片上评估。

本课提供了易于扩展到真实浏览器的脚手架代码。

## 使用它

`code/main.py` 是毕业课骨架：

- 动作 schema JSON 定义（10 种动作）。
- 用字典表示的模拟浏览器状态。

- 10 任务小型基准（合成页面），用于测量端到端成功率。
- 动作失败时的错误恢复钩子。

## 练习

1. 为动作 schema 增加一个 `screenshot_region` 工具（裁剪 + 缩放）。哪些任务会受益？

2. 阅读 AgentVista（arXiv:2602.23166）。描述最困难的任务类别，以及前沿模型为什么仍会失败。

3. 长时域记忆压缩：设计一个摘要链，最多保留 ≤4 张实时屏幕截图，日志可以保留任意数量。

4. 构建错误恢复钩子：动作失败（找不到按钮）时，智能体下一步做什么？

5. 在 10 个网页任务上比较纯屏幕截图的 Claude 4.7 与混合屏幕截图 + 无障碍树的 Qwen2.5-VL。分别在哪些任务上谁胜出？

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| GUI 定位 | “点击坐标” | 模型根据屏幕截图上的指令输出目标的（x,y） |
| 动作 schema | “工具定义” | 有效动作（点击、输入、滚动、拖动）的 JSON 描述 |
| 无障碍树 | “结构化 DOM” | 来自浏览器/iOS API、机器可读的 UI 层级 |
| 混合智能体 | “屏幕截图 + 树” | 同时使用图像与结构化信息，比任一单独方式更可靠 |
| 视觉工具使用 | “缩放/裁剪/检测” | 智能体在计划中途调用外部视觉工具（OCR、检测） |
| 摘要链 | “记忆压缩” | 定期用文本摘要替代很长的屏幕截图历史 |
| VisualWebArena | “端到端网页基准” | 2024 年端到端网页任务基准 |
| AgentVista | “2026 困难基准” | 12 个领域的真实工作流；即使 Gemini 3 Pro 也只有约 30% |
