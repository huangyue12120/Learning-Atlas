# Qwen-VL 家族与动态 FPS 视频

> Qwen-VL 家族——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是 2026 年最有影响力的开放视觉—语言模型谱系。每一代都押注一个决定性的架构选择，而开放生态的其他成员会在十二个月内复制它：通过 M-RoPE 实现原生动态分辨率、带绝对时间对齐的动态 FPS 抽样、ViT 中的窗口注意力，以及结构化智能体输出格式。到了 Qwen3-VL，这套方案已经稳定下来：带 2D-RoPE 的 ViT 编码器接收原生宽高比输入，通过 MLP 投影器连接到大型 Qwen3 语言基座，并把 OCR、定位和智能体行为作为一等目标进行训练。本课按时间顺序阅读这个家族，理解每个控制杆为什么这样设置。

**类型：** 学习
**语言：** Python（标准库，M-RoPE 编码器 + 动态 FPS 抽样器）
**前置课程：** Phase 12 · 06（patch-n'-pack）
**预计时间：** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三轴旋转（时间、高度、宽度），并解释为什么三个轴都需要。
- 为视频选择动态 FPS 抽样策略，并分析每秒词元数与事件检测准确率之间的关系。
- 按顺序说出 Qwen-VL 的四次代际升级，以及每次升级带来的能力。
- 接入 Qwen2.5-VL 风格的 JSON 智能体输出格式，并从 VLM 响应中解析结构化工具调用。

## 问题

Qwen-VL 于 2023 年 8 月发布，直接回应了 LLaVA-1.5 和 BLIP-2。Qwen 团队要解决的差距有三个方面：分辨率、视频和结构化输出。

分辨率：LLaVA-1.5 运行在 336x336。对照片足够，对中文发票或密集的电子表格截图却毫无用处。Qwen-VL 的第一项创新是 448x448 分辨率和有定位的边界框输出，让模型可以指出物体位置。

视频：Video-LLaMA 逐帧堆叠编码器，再将结果送入 LLM。对短片段有效，却不适合多分钟视频——因为时间轴才是其中的信号。Qwen 团队想要一个理解时间的单一编码器。

结构化输出：LLaVA 输出自由形式文本，而智能体需要 JSON。Qwen-VL 使用包括边界框坐标文本在内的显式 JSON 输出格式进行训练。

每一代 Qwen-VL 都沿着这三个轴之一扩展。

## 概念

### Qwen-VL（2023 年 8 月）

第一代使用 OpenCLIP ViT-bigG/14 作为编码器（25 亿参数）、与 LLaMA 兼容的 Q-Former（用 256 个查询执行 1 步）和 Qwen-7B 基座。贡献包括：

- 448x448 分辨率（当时是开放 VLM 的 SOTA）。
- 定位：在图文对上使用显式坐标词元输出进行训练，例如“The cat is at <box>(112, 204), (280, 344)</box>”。
- 从一开始就进行中英双语训练。

当时的基准结果：英语能力可与 GPT-4V 竞争，在中文上占据主导。定位监督才是真正的重点。

### Qwen2-VL（2024 年 9 月）——M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率 ViT 编码器替换了固定分辨率 + Q-Former 堆栈。关键变化：

- 原生动态分辨率。ViT 接受任意 HxW，只要能被 28 整除（图像块 14，再做 2x 空间合并）。1120x672 的图像（40x24 个合并图像块）会产生 960 个视觉词元。不调整大小、不平铺、不使用缩略图。
- M-RoPE（多模态 RoPE）。每个词元携带三维位置（t、h、w），而不是一维位置。图像使用 t=0，视频使用 t=帧索引。RoPE 按每个轴的频率旋转 query/key 向量。不需要位置嵌入表。
- MLP 投影器。放弃 Q-Former，在合并后的图像块词元上使用两层 MLP。
- 动态 FPS 视频。默认按 1–2 FPS 抽样，但模型接受任意帧数。

结果是：Qwen2-VL-7B 在多个多模态基准上匹敌 GPT-4o，并在 DocVQA 上超过它（94.5 对 88.4）。架构改变是决定性的一步。

### Qwen2.5-VL（2025 年 2 月）——动态 FPS + 绝对时间

Qwen2.5-VL 的重大转向是视频。动态 FPS 不只是“需要时多抽几帧”。论文将其形式化为：

- 绝对时间词元。使用真实时间戳，而不是位置索引（帧 0、1、2……）。“在 0:04，猫跳起来。”模型会看到与帧词元交错的 `<time>0.04</time>` 词元。
- 动态 FPS。慢速素材按 1 FPS 抽样，动作素材按 4+ FPS 抽样。由用户或训练器选择，M-RoPE 负责适配。
- ViT 中的窗口注意力。空间注意力限定在窗口内（块内局部注意力）以提高吞吐；每隔几层加入全局注意力。
- 显式 JSON 输出格式。使用工具调用数据训练，例如 `{"tool": "click", "coords": [380, 220]}`，开箱即用地适合智能体。
- MRoPE-v2 缩放。位置随最大输入大小缩放，因此 10 分钟视频不会耗尽频率范围。

基准结果：Qwen2.5-VL-72B 在大多数视频基准上超过 GPT-4o，在文档上匹敌 Gemini 2.0，并在 GUI 定位上达到开放模型 SOTA（ScreenSpot：84% 准确率，而 GPT-4o 为 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一次巩固而非重造：更大的 LLM 骨干（Qwen3-72B）、扩充训练数据、更好的 OCR，以及通过 Qwen3“思考模式”实现的更强推理能力。ViT 和 M-RoPE 保持不变。论文重点讨论数据和训练相对于架构的改进。

这个谱系的启示是：到 2025 年，Qwen-VL 架构已经稳定。后续代际扩展的是算力和数据，而不是原语。

### M-RoPE 的数学

经典 RoPE 使用成对坐标，根据位置 `m` 旋转维度为 `d` 的 query `q`：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分成三个带。设 `d = 96`，给时间、高度、宽度各分配 32 个维度。每个带按自己的轴位置旋转。位于（t=5、h=10、w=20）的图像块，会在三个带上分别应用旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本词元使用 `t = text_index, h = 0, w = 0`（或归一化后的选择），保持兼容性。视频帧使用 `t = frame_time, h = row, w = col`。单图像使用 `t = 0`。

好处是：一个位置编码就能处理文本、图像和视频，不需要分支代码或不同的位置表。

### 动态 FPS 抽样逻辑

给定时长为 `T` 秒、目标词元预算为 `B` 的视频：

1. 计算能承受的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择满足 `fps <= fps_max` 的目标 FPS。
3. 如果运动剧烈（光流启发式或用户明确要求），选择更高 FPS；如果运动平缓，选择更低 FPS。
4. 按选定 FPS 均匀抽样，在帧之间插入 `<time>t</time>` 词元。

Qwen2.5-VL 会隐式学习这套逻辑，推理时由用户通过 `fps` 参数控制。一个 60 秒、4 FPS、每帧 81 个词元的动作序列共有 19440 个词元，可以放入 32k 上下文。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练明确针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：对模型输出执行 JSON.parse。相比之下，自由形式的“在 (1024, 512) 点击”需要正则表达式和歧义处理。这一转变正是 Qwen2.5-VL 的 ScreenSpot 分数从 Qwen2-VL 的 55% 跳到 84% 的原因。

## 使用它

`code/main.py` 实现：

- 为混合文本、图像块和视频帧的打包序列计算 M-RoPE 位置。
- 动态 FPS 抽样器：给定（时长、预算、运动级别），选择 FPS 并输出帧时间戳。
- 一个玩具 Qwen2.5-VL JSON 输出解析器，处理带坐标字段的工具调用响应。

运行它，然后在 5 分钟视频上把固定 FPS 换成动态 FPS，感受差异。

## 练习

1. 计算隐藏维度为 48（每个带 16 维、底数 theta 10000）时，位置（t=3、h=5、w=7）的 M-RoPE 旋转。展示每个带中前三对的旋转角度。

2. 一段 10 分钟的监控录像按 1 FPS 会产生多少帧？在 384 分辨率、3x 池化下总共有多少词元？Qwen2.5-VL 默认的 32k 上下文能处理它吗？

3. 为 30 秒网球回合、30 秒菜谱演示和 30 秒 UI 智能体录屏选择 FPS。使用动态 FPS 逻辑说明每项选择。

4. Qwen2.5-VL 完全放弃了 Q-Former。为什么简单 MLP 在 2025 年可行，而在 2023 年不可行？（提示：数据规模和编码器质量。）

5. 将三个 Qwen2.5-VL JSON 工具调用输出解析为 Python 字典。格式错误的 JSON 会怎样？Qwen cookbook 推荐什么恢复策略？

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| M-RoPE | “多模态 RoPE” | 隐藏维度中带有时间、高度和宽度分区的三维旋转位置嵌入 |
| 动态 FPS | “智能抽样” | 根据运动、时长和词元预算为每个视频选择帧抽样率 |
| 绝对时间词元 | “时间戳词元” | 在序列中交错插入的 `<time>t</time>`，让模型看到实际秒数而不是帧索引 |
| 窗口注意力 | “局部注意力” | 为了提速而限制在小窗口内的空间自注意力；周期性加入全局注意力 |
| 结构化智能体输出 | “JSON 模式” | 教会 VLM 输出带坐标和工具名称、可解析 JSON 的训练监督 |
| min_pixels / max_pixels | “分辨率边界” | Qwen2.5-VL 的逐请求控制项，用于限制总像素数并因此限制词元数 |
| 定位 | “指出它” | 将边界框坐标作为文本词元输出；从 Qwen-VL 第一代起使用 |
