# 任意分辨率视觉：Patch-n'-Pack 与 NaFlex

> 真实图像不是 224x224 的正方形。收据可能是 9:16，图表是 16:9，医学扫描可能是 4096x4096，手机截图是 9:19.5。2024 年以前 VLM 的答案是把所有图像调整为固定正方形，但这会丢掉让 OCR、文档理解和高分辨率场景解析有效的信号。NaViT（Google，2023）表明，可以用块对角掩码把不同分辨率的图像块打包到同一个 Transformer 批量中。Qwen2-VL 的 M-RoPE（2024）完全去掉了绝对位置表。LLaVA-NeXT 的 AnyRes 把高分辨率图像切成基础图像 + 子图像。SigLIP 2 的 NaFlex 变体（2025）如今是开放 VLM 中希望用一个检查点服务所有宽高比时的默认编码器。本课端到端实现 patch-n'-pack。

**类型：** 构建
**语言：** Python（标准库，图像块打包器 + 块对角掩码）
**前置课程：** Phase 12 · 01（ViT 图像块）、Phase 12 · 05（LLaVA）
**预计时间：** 约 120 分钟

## 学习目标

- 将可变分辨率图像批量中的图像块打包成一个序列，并构造块对角注意力掩码。
- 针对给定任务，在 AnyRes 平铺（LLaVA-NeXT）、NaFlex（SigLIP 2）和 M-RoPE（Qwen2-VL）之间做出选择。
- 在不调整大小的情况下，为 OCR、图表和摄影图像计算词元预算。
- 说出正方形调整大小的三种失败模式：文字被挤压、内容被裁剪、填充浪费词元。

## 问题

Transformer 需要序列。一个批量是长度相同的序列堆叠。如果图像都是 224x224，每次都会得到 196 个图像块词元，不需要填充，任务完成。用 224 训练、用 224 推理，就再也不用考虑分辨率。

但现实并不配合。文档是纵向的（8.5x11 英寸，大约 2:3），图表截图是横向的（16:9），收据又高又窄（1:3），医学成像以 2048x2048 或更大的分辨率提供，移动设备截图则是 1170x2532（0.46:1）。

2024 年以前有三种选择，而每一种都会失败：

1. 调整到固定正方形（224x224 或 336x336）。挤压会扭曲文字和脸部；缩小会破坏图表标签和 OCR 内容。LLaVA-1.5 之前这是标准做法。
2. 裁剪为固定宽高比。这样会丢掉大部分图像，而选择裁剪位置本身也是一个视觉问题。
3. 填充到最长边。它修复了形变，但对于纵向图像，50% 以上的词元都会浪费在填充上。所有填充词元仍然参与二次复杂度的注意力计算。

2024–2025 年的答案是：让 Transformer 在图像的原生分辨率上处理图像块，并找出一种把异构批量打包成单个序列的方法，不浪费计算。

## 概念 <!-- learning-atlas: the-concept -->

### NaViT 与 patch-n'-pack

NaViT（Dehghani 等，2023）是第一篇展示这一方法能够规模化的论文。这个想法是机械的：

1. 对批量中的每张图像，以选定的图像块大小（例如 14）计算其原生图像块网格。
2. 将每张图像的图像块展平为自己的可变长度序列。
3. 将所有图像的图像块拼接为该批量的一条长序列。
4. 构造块对角注意力掩码，使图像 A 的图像块只能在图像 A 内相互关注。
5. 携带逐图像块的位置信息（2D RoPE 或分数位置嵌入）。

一个由 336x336（576 个词元）、224x224（256 个词元）和 448x336（768 个词元）三张图像组成的批量，会变成一条长度为 1600 的序列，配有 1600x1600 的块对角掩码。不需要填充，不浪费计算，Transformer 可以处理任意宽高比。

NaViT 还引入了训练期间的分数图像块丢弃——在批量中随机丢掉 50% 的图像块——这既能正则化，又能加速训练。SigLIP 2 继承了它。

### AnyRes（LLaVA-NeXT）

LLaVA-NeXT 的 AnyRes 是一种务实的替代方案。给定一个高分辨率图像和一个固定编码器（336 的 CLIP 或 SigLIP），按以下方式平铺图像：

1. 从预定义集合中选择最适合图像宽高比的网格布局——(1x1)、(1x2)、(2x1)、(1x3)、(3x1)、(2x2) 等。
2. 将整张图像切成该网格，每个图块变成一个 336x336 的裁剪图。
3. 另外生成一张缩略图：将整张图像调整到 336x336，作为全局上下文词元。
4. 用冻结的 336 编码器编码每个图块。拼接图块词元和缩略图词元。

对于 2x2 网格 + 缩略图的 672x672 图像：4 * 576 + 576 = 2880 个视觉词元。它成本高但有效——LLM 同时能看到局部细节和全局上下文。

当编码器被冻结且只支持一种分辨率时，AnyRes 是首选方案。但它会让大图像的词元数量爆炸（4x4 网格的 1344x1344 图像会产生 9216 + 576 ≈ 9800 个词元，填满 8k LLM 上下文的大部分）。

### M-RoPE（Qwen2-VL）

Qwen2-VL 引入了多模态旋转位置嵌入。不同于 NaViT 的分数位置或 AnyRes 的图块加缩略图方式，每个图像块携带三维位置（时间、高度、宽度）。query/key 的旋转处理任意 H、W 和时间长度。

M-RoPE 无需重新训练就能提供原生动态分辨率。推理时可以输入任意 HxW 的图像，图像块嵌入器产生 H/14 x W/14 个词元，每个词元得到自己的（t=0、行、列）位置，RoPE 用正确的频率旋转注意力，过程就完成了。Qwen2.5-VL 和 Qwen3-VL 延续了这一做法。InternVL3 的 V2PE 是相同思想在不同模态上的可变编码版本。

与 AnyRes 不同，M-RoPE 在原生分辨率下的词元数为 O(H x W / P^2)，没有乘法式图块开销。与 NaViT 不同，它仍然期望一次前向只处理一张图像。不同分辨率之间的批处理仍需要在其上使用 patch-n'-pack。

### NaFlex（SigLIP 2）

NaFlex 是 SigLIP 2 检查点的原生灵活模式。一个模型在推理时可以服务多个序列长度（256、729、1024 个词元）。其内部在训练期间使用 NaViT 风格的 patch-n'-pack，并为每个图像块使用绝对分数位置。它的卖点是：一个检查点，在推理时可以根据任务选择词元预算。

语义任务（分类、检索）使用 256 个词元；OCR 或图表理解使用 1024 个词元。不需要重新训练。

### 打包掩码

块对角掩码是大多数实现最容易出错的地方。对于覆盖图像 `i=0..B-1`、长度为 `n_i` 的长度 `N_total` 打包序列，形状为 `(N_total, N_total)` 的掩码 `M` 在两个索引属于同一图像块时为 1，否则为 0。可以根据累积长度列表构造：

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]
```

在 PyTorch 中，可以用 `torch.block_diag` 或显式 gather 一行完成。FlashAttention 的可变长度路径（`cu_seqlens`）完全跳过掩码，直接使用累积长度张量在各序列内部做注意力——对典型批量而言，比稠密掩码快约 10 倍。

### 词元预算

根据任务选择策略：

- OCR / 文档：1024–4096 个词元。使用 1024 词元的 SigLIP 2 NaFlex，或 AnyRes 3x3 + 缩略图。
- 图表和 UI：384–448 原生分辨率下的 729–1024 个词元。使用带最大像素数上限的 Qwen2.5-VL 动态分辨率。
- 自然照片：256–576 个词元足够。下游 LLM 能看到足够的信息，应当在内容密度高的地方支付词元成本。
- 视频：空间池化后每帧 64–128 个词元，2–8 FPS。第 12.17 课会讲到这一点。

2026 年的生产规则是：为每个任务设定 max-pixels 上限，以原生宽高比编码，直到达到该上限；将批量打包并跳过填充。Qwen2.5-VL 正是通过 `min_pixels` 和 `max_pixels` 暴露这个控制杆。

## 使用它

`code/main.py` 用整数像素坐标为异构图像批量实现 patch-n'-pack。它会：

- 接收一组（H、W）图像尺寸。
- 使用图像块大小 14 计算每张图像的图像块序列长度。
- 将它们打包成总长度为 `sum(n_i)` 的一个序列。
- 构造块对角注意力掩码（为了清晰而使用稠密实现）。
- 比较打包成本与正方形调整大小和 AnyRes 平铺的成本。
- 为混合批量（收据、图表、截图、照片）打印词元预算表。

运行它。输出的数字就是为什么每个 2026 年开放 VLM 都使用 patch-n'-pack 的原因。

## 练习

1. 一张收据大小为 600x1500（1:2.5）。图像块大小为 14 时有多少个原生分辨率词元？调整到 336 的正方形后有多少个？在实际中哪一种会损失更多 OCR 准确率？

2. 为长度分别为 256、576、729、1024 的四张图像构造块对角掩码。验证注意力矩阵为 2585x2585，并且恰好有 `256^2 + 576^2 + 729^2 + 1024^2` 个非零元素。

3. 对于一张 1792x896、图像块大小为 14 的图像，比较：（a）调整到 336 正方形后编码；（b）AnyRes 2x1 + 缩略图；（c）原生 M-RoPE。哪一种使用的词元最少？哪一种保留的细节最多？

4. 实现分数图像块丢弃：给定一个打包序列，均匀随机丢掉 50% 的词元，并相应更新块对角掩码。测量掩码稀疏度的变化。

5. 阅读 Qwen2-VL 论文第 3.2 节（arXiv:2409.12191）。用两句话说明 `min_pixels` 和 `max_pixels` 控制什么，以及为什么两个边界都重要。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| Patch-n'-pack | “NaViT 风格打包” | 将不同图像的可变长度图像块序列拼接到同一个批量维度 |
| 块对角掩码 | “打包掩码” | 限制每张图像的图像块只能关注自己、不能关注打包序列中邻居的注意力掩码 |
| AnyRes | “LLaVA-NeXT 平铺” | 将高分辨率图像切成固定大小图块网格，再加一张全局缩略图，用固定编码器编码每个图块 |
| NaFlex | “SigLIP 2 原生灵活” | 单个 SigLIP 2 检查点在推理时无需重新训练即可提供 256/729/1024 词元预算 |
| M-RoPE | “多模态 RoPE” | 处理任意 H、W、T 且不需要位置表的三维旋转位置编码（时间、行、列） |
| cu_seqlens | “FlashAttention 打包” | FlashAttention 可变长路径用来替代稠密块对角掩码的累积长度张量 |
| min_pixels / max_pixels | “分辨率边界” | Qwen2.5-VL 为每个请求设置的控制杆，用于限制很小或很大输入的词元数量 |
| 视觉词元预算 | “每张图像有多少词元” | 每张图像产生的图像块词元的大致数量；决定 LLM 的提示词预算和注意力成本 |
