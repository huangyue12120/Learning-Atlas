# 工具接口——智能体为何需要结构化 I/O

> 语言模型生成 token，程序执行动作。连接二者的缺口就是工具接口：它是一份让模型请求动作、让宿主执行动作的契约。2026 年的每一套技术栈——OpenAI、Anthropic 和 Gemini 的函数调用，MCP 的 `tools/call`，A2A 的任务部分——都只是同一个四步循环的不同编码。本课将命名这个循环，并展示运行它所需的最小机制。

**类型：** 学习
**语言：** Python（标准库，无 LLM）
**前置课程：** Phase 11（LLM 完成 API）
**时间：** 约 45 分钟

## 学习目标

- 解释为什么只能生成文本的 LLM 无法自行对现实世界采取行动。
- 画出四步工具调用循环（描述 → 决策 → 执行 → 观察），并说明每一步由谁负责。
- 将工具描述写成三个部分：名称、JSON Schema 输入，以及确定性的执行器函数。
- 区分纯工具与有副作用的工具，并说明这种划分为何关系到安全性。

## 问题

LLM 输出的是关于下一个 token 的概率分布，这就是它全部的输出表面。如果你问聊天模型“现在班加罗尔的天气怎么样”，它可以写出一句貌似合理的话，却不能接入天气 API。这句话可能只是碰巧正确，也可能已经过时三天。

工具接口的目的就是填补这个缺口。宿主程序——你的智能体运行时、Claude Desktop、ChatGPT、Cursor 或自定义脚本——向模型公布一组可调用工具。模型判断需要采取行动时，会输出一个结构化载荷，指出工具及其参数。宿主解析该载荷，真正运行工具，再把结果送回模型。只要模型认为还需要调用，循环就继续。

这份契约的第一个版本于 2023 年 6 月以 OpenAI 的 `functions` 参数发布。Anthropic 随后在 Claude 2.1 中加入 `tool_use` 块。几个月后 Gemini 加入了 `functionDeclarations`。如今每个提供商都暴露出同一种形状：输入是一组由 JSON Schema 描述类型的工具，输出是一个 JSON 载荷形式的工具调用。Model Context Protocol（2024 年 11 月）将这份契约泛化，使一个工具注册表可以服务于每个模型。A2A（2026 年 4 月，v1.0）又将同一原语用于智能体之间的委派。

四步循环是这些机制底层不变的结构。Phase 13 的其他内容都是对它的展开。

## 概念

### 第一步：描述

宿主为每个工具声明三个字段。

- **名称。** 稳定、机器可读的标识符。使用 `get_weather`，不要使用“天气东西”。
- **描述。** 一段自然语言简介，例如“当用户询问特定城市的当前天气时使用。不要用于历史数据”。
- **输入 schema。** 描述工具参数的 JSON Schema 对象（draft 2020-12）。

模型会收到这份列表。现代提供商会使用各自的模板，将这些声明序列化到系统提示中；因此作为调用方，你只需要处理结构化形式。

### 第二步：决策

模型根据用户消息和可用工具，选择三种行为之一。

1. **直接用文本回答。** 不调用工具。
2. **调用一个或多个工具。** 输出结构化的调用对象。在 `parallel_tool_calls: true`（OpenAI 和 Gemini 默认开启，Anthropic 需显式选择）时，模型可以在一个回合中输出多个调用。
3. **拒绝。** 严格模式的结构化输出可以产生带类型的 `refusal` 块，而不是调用。

工具调用载荷有三个稳定字段：调用 `id`、工具 `name` 和 JSON `arguments` 对象。之所以需要 id，是为了让宿主可以把之后的结果对应到具体调用；并行调用返回顺序不一致时尤其重要。

### 第三步：执行

宿主收到调用后，会根据声明的 schema 校验参数，然后运行执行器。参数无效意味着模型臆造了字段或使用了错误类型——这是弱模型非常常见的失败模式。生产级宿主通常会采取三种处理之一：快速失败并把错误呈现给模型；使用受约束的解析器修复 JSON；或者把校验错误放入提示后重试模型。

执行器本身就是普通代码：Python、TypeScript、shell 命令或数据库查询。它产生一个结果，通常是字符串，但也可以是任意 JSON 值或结构化内容块（MCP 中的文本、图像或资源引用）。结果必须可序列化。

### 第四步：观察

宿主将工具结果追加到对话中（作为带有匹配 `id` 的 `tool` 角色消息），然后再次调用模型。模型现在可以在上下文中看到工具输出，并生成最终答案或请求更多调用。这个过程会持续到模型不再输出调用，或者宿主达到迭代次数的安全上限。

### 信任划分

从安全角度看，工具有两类。

- **纯工具。** 只读、确定性、无副作用。`get_weather`、`search_docs`、`get_current_time` 都属于此类，可以安全地推测性调用。
- **后果性工具。** 会修改状态、花费金钱或接触用户数据。`send_email`、`delete_file`、`execute_trade` 都属于此类，必须设置闸门。

Meta 在 2026 年提出的智能体安全“Rule of Two”规定：一个回合最多只能同时包含以下三项中的两项：不可信输入、敏感数据、后果性动作。工具接口正是执行这条规则的地方——你可以拒绝调用、要求用户确认或提升权限范围。完整的安全章节见 Phase 13 · 15，智能体层面的权限策略见 Phase 14 · 09。

### 循环位于哪里

| 上下文 | 谁负责描述 | 谁负责决策 | 谁负责执行 |
|---------|---------------|-------------|--------------|
| 单回合函数调用（OpenAI/Anthropic/Gemini） | 应用开发者 | LLM | 应用开发者 |
| MCP | MCP 服务器 | 通过 MCP 客户端的 LLM | MCP 服务器 |
| A2A | Agent Card 发布者 | 发起调用的智能体 | 被调用的智能体 |
| Web 浏览器（函数调用智能体） | 浏览器扩展 / WebMCP | LLM | 浏览器运行时 |

无论在哪里，都是同样的四个步骤。列名会变化，结构不会。

### 为什么不直接提示模型输出 JSON？

“让模型用 JSON 回复”是函数调用出现前的做法。即使对前沿模型，它也有约 5% 到 15% 的失败率，在更小的模型上还要高得多。失败形式包括缺少大括号、尾随逗号、臆造字段和错误类型。之后你还需要 JSON 修复、重试或受约束的解码器。

原生函数调用更好有三个原因。第一，提供商会针对确切的调用形状端到端训练模型，因此严格模式下的合法 JSON 比例可升至 98% 到 99%。第二，调用载荷位于独立的协议槽中，而不是自由文本里，因此工具调用不会泄漏到用户可见的回复中。第三，提供商通过受约束解码来保证 schema 合规（OpenAI 的严格模式、Anthropic 的 `tool_use`、Gemini 的 `responseSchema`）。输出可以保证通过校验。

Phase 13 · 02 会并排讲解三个提供商的 API。Phase 13 · 04 会深入结构化输出。

### 断路器

当模型停止输出调用，或者宿主达到最大回合数时，循环会终止。生产级宿主通常将上限设在 5 到 20 个回合之间。超过这个范围，几乎可以肯定模型已经陷入无法退出的循环。Claude Code 默认是 20；OpenAI Assistants 是 10；Cursor 的智能体模式是 25。

另一种选择是无上限循环；每隔六个月就会出现一次“智能体整夜调用 API 花掉 400 美元”的复盘文章。没有上限不要上线。

Phase 14 · 12 会深入讲解错误恢复与自愈；Phase 17 会讲生产级速率限制。

## 动手使用

`code/main.py` 在没有 LLM 的情况下运行四步循环。一个假的“决策器”函数通过匹配用户消息来模拟模型；执行器、schema 校验器和观察步骤的测试工具都是真实的。运行它，可以看到带有可打印中间状态的完整请求/响应编排，然后在后续课程中将假的决策器替换为任何真实提供商。

请重点观察：

- 工具注册表为每个工具保存四项内容：名称、描述、schema 和执行器引用。
- 校验器只用标准库实现了一个最小 JSON Schema 子集（类型、required、enum、min/max）。Phase 13 · 04 会提供更完整的版本。
- 循环将迭代次数限制为五次。生产级智能体恰恰需要这种断路器。

## 交付物

本课会生成 `outputs/skill-tool-interface-reviewer.md`。给定一份工具定义草稿（名称 + 描述 + schema + 执行器概要），这个 skill 会审查它是否适合该循环：名称是否稳定且适合机器使用，描述是否完整说明了用法，schema 是否正确使用 JSON Schema 2020-12，以及纯工具与后果性工具的分类是否明确。

## 练习

1. 在 `code/main.py` 中添加第四个工具 `get_stock_price(ticker)`。将描述写成“当用户按 ticker 询问当前股价时使用。不要用于历史价格或市场概览”。运行测试工具，确认提到 ticker 的查询会被假的决策器路由到新工具。

2. 破坏 schema 校验器。传入一个缺少必填字段的调用，确认宿主在执行前拒绝它；再传入一个带额外未知字段的调用。做出判断：宿主应该拒绝还是忽略？用安全性论证你的选择。

3. 将测试工具中的每个工具分类为纯工具或后果性工具。给需要的注册表条目添加 `consequential: true` 标志，并修改循环：每当选中后果性工具时，打印一行“将向用户确认”。这就是每个生产级宿主都需要的确认闸门形状。

4. 在纸上画出上面的四步循环，并为你最喜欢的客户端（Claude Desktop、Cursor、ChatGPT 或自定义技术栈）填写提供商列的表格。与 Phase 13 · 06 中 MCP 特有的变体交叉对照。

5. 从头到尾阅读 OpenAI 的函数调用指南。找出一个位于请求中、但不在这里呈现的四步循环中的字段。解释它增加了什么，以及为什么它是便利功能而非必需品。

## 术语

| 术语 | 人们常说 | 实际含义 |
|------|----------------|------------------------|
| 工具 | “模型可以调用的东西” | 由名称 + JSON-Schema 类型输入 + 执行器函数组成的三元组 |
| 函数调用 | “原生工具使用” | 提供商级 API，用于输出结构化工具调用而不是散文 |
| 工具调用 | “模型要求采取行动” | 模型输出的、带有 `id`、`name`、`arguments` 的 JSON 载荷 |
| 工具结果 | “工具返回的内容” | 执行器的输出，被包装进带有匹配 id 的 `tool` 角色消息 |
| 并行工具调用 | “一次调用很多个” | 同一个模型回合中的多个调用对象，可以按 id 独立排序 |
| 严格模式 | “保证 JSON” | 迫使模型输出通过声明 schema 校验的受约束解码 |
| 纯工具 | “只读工具” | 无副作用，可以安全重跑 |
| 后果性工具 | “动作工具” | 修改外部状态，需要闸门、审计或用户确认 |
| 四步循环 | “工具调用循环” | describe → decide → execute → observe |
| 宿主 | “智能体运行时” | 持有工具注册表、调用模型并运行执行器的程序 |
