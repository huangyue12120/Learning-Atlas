# 缩放定律

> 2020 年的 Kaplan 论文说：模型越大，损失越低。2022 年的 Hoffmann 论文说：你的训练远远不够。计算资源要分到参数与词元两个桶中，而如何分配并不显而易见。

**类型：** 学习  
**学习实现：** Python  
**前置课程：** Phase 7 第 05 课（完整 Transformer）、Phase 7 第 07 课（GPT）  
**预计时间：** 约 45 分钟

## 问题

当你拥有 C FLOPs 的训练算力，并希望训练出效果最好的模型时，需要调整两个旋钮：

1. **参数量（N）应该是多少？** 模型越大，容量越高。
2. **训练词元量（D）应该是多少？** 数据越多，容量利用得越充分。

FLOPs 近似按 `6 × N × D` 缩放。可以增大 N、减小 D，也可以增大 D、减小 N。哪一种更好？

2022 年以前，答案是“尽力增大 N”。GPT-3（2020）有 175B 参数，使用约 300B 词元训练，比例约为每个参数 1.7 个词元。Kaplan 缩放定律支持这种做法。

Hoffmann 等（2022）训练了一组名为 Chinchilla 的小模型，却得到不同结论：最优比例更接近**每个参数 20 个词元**。GPT-3 的训练量低了 10 倍。Chinchilla（70B 参数、1.4T 词元）在每个基准上都胜过 GPT-3（175B 参数、300B 词元），推理成本还低 2.5 倍。

2026 年属于 Chinchilla——但有一个重要转折。Llama 3 8B 使用 15 万亿个词元训练，比例为每个参数 1,875 个词元，是 Chinchilla 最优值的 94 倍。对大规模使用的模型而言，推理成本比训练成本更重要，因此让更小、易部署的模型进行超过 Chinchilla 最优点的过度训练，已经成为 2026 年的默认选择。

## 概念

![Chinchilla 曲线：不同 N/D 比例下损失与算力的关系](../assets/scaling-laws.svg)

### Hoffmann 定律

根据 Chinchilla 论文，损失满足：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 参数量（不含嵌入参数）。
- `D` = 训练词元量。
- `α ≈ 0.34`、`β ≈ 0.28`（大致对称）。
- `E ≈ 1.69`，不可约损失下限。
- `A ≈ 406`、`B ≈ 411`。

随着规模扩大，这两项需要相互权衡。在算力固定（C = 6ND）时对 `N` 求导并求解：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

计算最优解为：每个参数 20 个词元。

### 为什么仍要过度训练

Chinchilla 最优点最小化的是每个训练 FLOP 对应的训练损失。但训练成本只支付一次，推理成本却要一直支付。

对于每月服务一万亿词元的聊天机器人，推理成本会主导总成本。Llama 的做法是：把模型做小、把训练做长。使用 15T 词元训练的 8B 模型深度优化了推理成本：

- 可以装入消费级 GPU。
- 延迟只有 Chinchilla 最优 70B 模型的一小部分。
- 对多数任务而言，质量已经足够接近。

DeepMind 2024 年的论文《Over-training is the new optimal》对这一点进行了形式化分析。对于推理占主导的工作负载，合适的比例更接近每个参数 100～500 个词元，具体取决于服务量。

### 涌现与平滑性

一种观点认为：某些能力（算术、多步推理、遵循思维链）会在达到某个规模后突然“涌现”。

Schaeffer 等（2023）认为这是测量造成的假象：涌现指标使用了不连续的评分方式（精确匹配、阈值准确率），掩盖了底层 logits 的平滑改善。连续指标（交叉熵）显示的是平滑曲线。

2026 年的共识是：通过连续损失进行预测是可靠的；基准分数的跳变往往来自评分器。应依据连续指标规划预算。

### 2026 年的全景

缩放定律仍然有效，但以下因素发生了变化：

| 因素 | 变化方式 |
|------|----------|
| 数据质量 | 筛选“优质”词元（Phi 风格）可使有效算力曲线移动超过 2 倍 |
| MoE | 总参数量与活跃 FLOPs 解耦；缩放定律按活跃 FLOP 计算 |
| 后训练 | 某些能力（指令遵循、代码）受 SFT+RLHF 的影响大于预训练 |
| 多模态 | 图像与文本词元共同缩放；每种模态有独立曲线 |
| 合成数据 | 模型生成训练数据；有效算力可以产生复合增益 |

Muon 优化器（Kimi Moonlight，2024）在相同数据量下，相比 AdamW 展现出约 2 倍有效算力增益。2026 年的一些训练任务已默认使用 Muon。它改变的是缩放定律中的绝对常数，而不是曲线形状。

## 动手构建

参见 `code/main.py`。我们将实现 Chinchilla 损失方程，并在多个算力预算下求解计算最优的 `(N, D)`。

### 第 1 步：Chinchilla 损失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定 `C = 6ND` 时，绘制 `L` 关于 `(N, D)` 的等高线，并找出最小值。

### 第 2 步：计算最优前沿

对从 `1e17` 到 `1e25` FLOPs 的算力预算，寻找在约束 `6ND = C` 下使损失最小的 `(N, D)`。验证比例 `D/N ≈ 20`。

### 第 3 步：过度训练成本

计算训练一个小 10 倍的模型时付出的额外损失（N 为最优值的 1/10，D 为最优值的 10 倍）。同时报告由此换得的推理 FLOP 节省量（与 N 成正比）。

### 第 4 步：与真实模型比较

代入 GPT-3、Chinchilla、Llama 3 8B 和 DeepSeek-V3（活跃参数）的已知 `(N, D)`，比较预测损失与报告损失。

## 使用方法

你不太可能亲自训练前沿模型，但缩放定律可以告诉你：

1. **微调数据是否足够。** 如果特定任务数据量低于基础模型每个参数 20 个词元，损失很可能会在某个下限饱和。
2. **是否应该选择更大的基础模型。** 如果全部预算都花在推理上，应优先选择规模更小、训练更久的模型。
3. **收益会在何处递减。** 超过 Chinchilla 最优值 1000 倍后，对数损失的变化会淹没在噪声中。

**2026 年的研究轨迹：**

- **数据受限区间。** 互联网中的高质量词元数量有限（过滤后英文约 5～10 万亿）。前沿预训练正接近这一上限。下一批杠杆将是合成数据、多语种数据、多模态数据和扩大 RLHF 微调规模。
- **算力倍增技巧。** Muon 优化器、MoE、更好的数据筛选——每一种都改变绝对常数，而不是渐近线。
- **RL 的缩放定律。** 仍是开放问题。早期证据表明，RL 样本也遵循幂律，但指数与预训练差异很大。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------|----------|
| 参数量（N） | “模型大小” | 不含嵌入的权重数量；决定容量。 |
| 词元量（D） | “训练数据” | 训练期间见过的词元数量；决定参数利用得有多充分。 |
| 算力（C） | “花费的 FLOPs” | 对标准 Transformer 约为 `6 × N × D`。 |
| Chinchilla 最优 | “D/N ≈ 20” | 让每个预训练 FLOP 对应损失最小的比例。 |
| 过度训练 | “超过 Chinchilla 最优点” | 花费更多训练 FLOPs 来节省推理 FLOPs；D/N >> 20。 |
| 不可约损失 | “下限” | 缩放定律中的 `E` 项；数据自身的熵。 |
| 涌现能力 | “规模扩大时突然跳变” | 往往是评分器造成的假象；连续损失是平滑的。 |
| 有效算力 | “训练效率倍增器” | 更好的数据、优化器或架构会提高每个 FLOP 的效用。 |
