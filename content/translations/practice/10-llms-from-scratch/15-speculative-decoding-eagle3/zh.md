# 推测解码与 EAGLE-3

> 第 7 阶段第 16 课证明了数学结论：Leviathan 拒绝规则能够精确保持验证器的分布。本课从训练栈角度理解 2026 年生产环境中的推测解码。EAGLE-3 将草稿模型从廉价近似变成了一个专门的小型网络：它在验证器自己的隐藏状态上训练，然后加入训练时测试循环，使训练分布与推理分布对齐。结果是端到端加速 3× 到 6.5×，聊天场景的每词元接受率超过 0.9，而且没有分布权衡。2026 年的每个生产级推理栈默认都会发布它。

**类型：** 构建
**语言：** Python（标准库）
**前置课程：** 第 7 阶段第 16 课（推测解码数学）、第 10 阶段第 12 课（推理优化）
**预计时间：** 约 75 分钟

## 学习目标

- 用一句话陈述 Leviathan 定理，并证明推测循环产生的样本与验证器的样本完全同分布。
- 梳理从原始推测解码（Leviathan，2023）到 EAGLE、EAGLE-2 和 EAGLE-3 的两年演进，并说出每一步移除了哪项确切限制。
- 根据接受率 `α` 和草稿–验证器成本比 `c` 计算期望加速比，并为每种场景选择最佳草稿长度 `N`。
- 从零实现完整的推测循环：起草、验证、从残差分布拒绝采样、被拒绝时回滚 KV 缓存，以及全部接受时发出额外词元。

## 问题

在 70B 模型上进行自回归解码时，H100 上的速度可能只有每秒 35 个词元。GPU 远未饱和，瓶颈是内存带宽：每生成一个词元，就要从 HBM 加载 700 亿个参数的权重，做一步计算，再生成一个浮点数。计算单元大部分时间都在空闲。

推测解码把它变成了一个可以实际解决的吞吐量问题。廉价的草稿模型用 N 次小型前向传播提出 N 个词元；验证器在一次前向传播中运行，处理前缀和全部 N 个草稿。如果验证器在位置 i 的分布与草稿一致（我们会精确定义“ 一致”），就接受；否则从残差分布中采样一个修正。一轮大型模型前向传播最多可以产生 N+1 个接受的词元，而不是一个。

Leviathan、Kalman、Matias（ICML 2023）的定理表明，输出分布与直接从验证器采样得到的分布完全相同。因此，推测解码只优化延迟，不牺牲质量，可以用于生产环境。

第 7 阶段第 16 课给了你数学，本课给你训练栈。一个优秀的草稿能带来比廉价草稿高 2 倍的加速。EAGLE、EAGLE-2 和 EAGLE-3（Li 等，2024–2025）把“草稿 = 同一模型的更小版本”变成了一套精确的工程纪律。2026 年的生产推理服务器默认使用 EAGLE-3。

## 概念

### 不变量：Leviathan 拒绝采样 <!-- learning-atlas: the-invariant-leviathan-rejection-sampling -->

设 `p(t)` 是给定某个前缀时草稿模型对下一个词元的分布，`q(t)` 是验证器的分布。从 `p` 中采样草稿词元 `d ~ p`，以 `min(1, q(d) / p(d))` 的概率接受。拒绝时，从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。最终样本服从 `q`。无论 `p` 有多差，这都成立——它越差，拒绝越频繁，但输出仍然是精确的。

将 N 次调用串接起来，在一次验证器前向传播中处理 `prefix + d_1 + ... + d_N`。验证器会同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历；在位置 `j` 第一次拒绝时，从 `residual(q_j, p_j)` 中采样并停止。全部接受时，从 `q_{N+1}` 中采样一个额外词元。

### 什么决定加速比

设 `α` 是每个草稿词元的期望接受率，设 `c = cost(draft) / cost(verifier)` 是成本比。每次验证器前向传播接受的词元数期望为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个接受词元的期望总耗时为 `(N * c + 1) / E[accepted]`。对 `N` 最小化这个量，就能得到甜蜜点。当 `α = 0.8, c = 0.05` 时，最佳 `N` 约为 5–7，加速比为 3.2×。当 `α = 0.95, c = 0.02` 时，最佳 `N` 约为 8–10，加速比接近 5×。

最大的杠杆是 `α`。在固定 `N = 5` 时，将 `α = 0.6`（原始草稿）提升到 `α = 0.9`（EAGLE-3）会让每次验证器前向传播的期望接受词元数从 2.2 变为 4.1。使用同一个验证器，吞吐量几乎提升 2 倍。

### 两年的演进

**原始推测解码（Leviathan，2023）。** 草稿模型是一个从同一模型家族独立训练出来的小型 LLM。接线简单，`α ≈ 0.6`，加速比最多约 2×。

**EAGLE-1（Li 等，2024）。** 草稿模型是一个很小的 Transformer，通常只有一两层；它将验证器最后一层的隐藏状态作为输入，直接预测下一个词元。由于草稿看到了验证器的特征表示，其分布与验证器更加接近，`α` 提升到 0.7–0.8。

**EAGLE-2（Li 等，2024）。** 加入动态草稿树：不再提出一条长度为 N 的候选序列，而是提出一个小型候选树，在一次前向传播中用验证器对每个候选评分（树注意力），然后沿概率最高的路径前进。草稿长度会随每一步自适应。沿接受路径的每词元 `α` 超过 0.85。

**EAGLE-3（Li 等，2025，NeurIPS）。** 又有两项变化。第一，完全移除特征预测损失——EAGLE-1/2 训练草稿去匹配验证器隐藏状态，这限制了数据继续增加的收益。EAGLE-3 直接训练词元预测。第二，训练时测试（TTT）：训练草稿时，在多步过程中把草稿自己的前序预测反馈为输入，就像它在推理时的运行方式一样。这使训练分布和测试分布对齐，并阻止误差累积。测得的加速比：聊天场景最高 6.5×；在 H100 上、SGLang 的 batch 64 中吞吐量提升 38%。

### KV 缓存回滚

验证会在一次前向传播中将验证器的 KV 缓存扩展 N 个条目。如果在位置 `j` 发生拒绝，那么位置 `j-1` 之后的缓存内容就已经错误。两种常见实现是：写入临时缓冲区，并在接受时提交（vLLM、TensorRT-LLM）；或保留物理 KV 缓存，同时维护逻辑长度，拒绝时截断。无论哪种方式，回滚成本都只是每层每头的字节数，与前向传播成本相比可以忽略。

对于 EAGLE-2 树搜索，验证器使用遵守树拓扑的非因果掩码运行注意力。工程实现很琐碎，但计算仍是一次带自定义掩码的标准 flash-attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|----------|-----------|-----|---------|---------------|
| 原始方案 | 独立的小型 LLM | 0.55-0.70 | 1.8-2.3× | 无（复用已有小模型） |
| Medusa | 验证器上的额外 LM 头 | 0.65-0.75 | 2-3× | 约 1B 个 SFT 词元 |

## 动手实现

见 `code/main.py`。这里实现了完整的 Leviathan 推测循环，包含所有组件：N 词元起草、验证器并行前向、逐位置拒绝、残差采样、额外词元、KV 回滚，以及验证输出分布与直接从 `q` 采样所得分布相匹配的经验检查。

### 步骤 1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤 2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤 3：完整的推测步骤

`spec_step` 函数从 `p` 中起草 N 个词元，然后在一次并行的 `q` 评估中验证全部词元。它对每个草稿词元应用拒绝规则，第一次拒绝时从残差中采样修正。如果全部接受，则从 `q_{N+1}` 中采样一个额外词元。

### 步骤 4：KV 回滚记账

模拟器为每个 worker 追踪一个逻辑 `kv_length`。接受 `k` 个草稿时，`kv_length += k`。在位置 `j` 拒绝时，缓存已经写过了 `j` 之后的位置，但逻辑长度会被设为 `prefix_length + j + 1`——也就是修正词元之后的位置。后续读取会截断到这个逻辑长度。

### 步骤 5：Leviathan 检查

运行 50,000 次推测步骤，统计接受词元的经验分布；再从 `q` 中直接采样 50,000 次进行比较。卡方统计量应远低于临界值。定理在实践中通过了检查。

### 步骤 6：加速比与 α

通过以不同幅度扰动 `p` 使它偏离 `q`，扫描草稿质量。测量 `α`，然后绘制接受词元数期望随 `α` 和 `N` 变化的曲线。代码会打印一张表，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何解锁每次验证器调用 4–5 个词元。

## 使用它

使用 EAGLE-3 的生产级 `vllm serve`：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在 H100 上、batch 64 的 SGLang 使用 EAGLE-3 时，相比 batch-64 的原始解码，吞吐量大约高 1.38×，这是 EAGLE-3 论文中的数据。

适合使用推测解码的场景：

- 任何 p50 延迟比峰值吞吐更重要的交互式聊天工作负载。
- 代码生成和结构化输出（JSON、SQL）。目标分布高度可预测，因此 `α` 高于 0.9。
- 长文本生成（数千个词元）。摊销后的加速会持续产生收益。

不适合的场景：

- 非常小的模型（< 3B）。草稿模型并没有比验证器便宜太多。
- 极小的 batch-1 CPU 部署。草稿模型的内存开销可能不值得。
- 温度很高的创意采样，此时 `α` 会崩溃。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| Leviathan rule | “min(1, q 除以 p)” | 以 `min(1, q(d)/p(d))` 的概率进行伯努利接受/拒绝；拒绝时从残差采样，就能精确保持验证器分布 |
| Residual distribution | “(q 减 p) 的正部，再归一化” | 将 `(q - p)_+` 截断为非负并重新归一化；拒绝时要从这里采样 |
| Acceptance rate α | “草稿有多常正确” | 拒绝规则下每词元伯努利成功概率的期望；决定所有加速数学 |
| EAGLE-1 | “隐藏状态草稿” | 以验证器最后一层隐藏状态为条件的小型 Transformer 草稿（Li 等，2024） |
| EAGLE-2 | “动态草稿树” | EAGLE-1 加上由树注意力在一次验证器前向传播中评分的候选延续树 |
| EAGLE-3 | “训练时测试” | 移除特征预测损失，直接训练词元预测，并在训练期间将草稿自己的输出反馈给它 |
| Training-time test（TTT） | “暴露偏差修复” | 在训练时自回归地运行草稿，使训练和测试输入分布一致；是 scheduled sampling 的直接对应物 |
| KV rollback | “撤销被拒绝的草稿” | 拒绝后将验证器 KV 缓存重置到已接受前缀长度的记账机制 |
| Bonus 词元 | “免费的那个” | N 个草稿全部接受时，从 `q_{N+1}` 采样的额外词元，不需要额外的验证器成本 |
| Tree attention | “一次验证多个候选” | 使用遵守草稿树拓扑的非因果掩码注意力；一次前向传播计算树中每个节点的 `q_i` |
