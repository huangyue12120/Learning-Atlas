# 多词元预测（MTP）

> 从 GPT-2 到 Llama 3，每个自回归 LLM 都在每个位置只计算一个损失：预测下一个词元。DeepSeek-V3 为每个位置增加了第二个损失：预测再下一个词元。671B 模型中额外的 14B 参数通过梯度流被蒸馏回主模型，训练好的 MTP 头又在推理时被改作推测解码草稿器，接受率超过 80%，生成吞吐量免费提升了 1.8 倍。本课根据 DeepSeek 技术报告构建顺序式 MTP 模块，计算损失与共享输出头的参数布局，并解释 MTP 如何保留因果链，而 Gloeckle 等人最初的并行 MTP 为什么破坏了这条链。

**类型：** 构建  
**语言：** Python（标准库）  
**前置课程：** 第 10 阶段 · 04（预训练一个迷你 GPT）、第 10 阶段 · 15（推测解码）  
**用时：** 约 60 分钟

## 学习目标

- 陈述 MTP 训练目标，推导跨预测深度的联合损失。
- 解释 Gloeckle 等人的并行 MTP 头（2024）与 DeepSeek-V3 顺序式 MTP 模块的差异，以及顺序设计为何保留因果链。
- 计算在预训练中加入 MTP 模块带来的参数与内存开销。
- 从零实现一个 MTP 模块：共享嵌入、每深度 Transformer 块、投影层和共享输出头。

## 问题

下一个词元预测是 LLM 的标准训练目标。每个隐藏状态只被监督去预测一件事：紧随其后的词元。这是一个出人意料的弱信号。一段序列的大部分信息都超出一个词元的范围——结构、连贯性、事实性和算术流向。模型必须在数万亿个词元上积累许多单词元信号，才能学会这些性质。

MTP 提出了一个问题：如果每个隐藏状态同时被监督去预测多个未来词元，会怎样？Gloeckle 等人（Meta，2024）证明这确实有帮助。他们在骨干网络上放置多个独立输出头，每个头预测不同偏移量。它简单、并行，但所有头看到的是同一个隐藏状态，没有层级式细化；预测也没有形成因果链，因此不能直接用于推测解码。

DeepSeek-V3（2024 年 12 月）将 MTP 重新设计为在每个预测深度保留因果链的顺序模块。模型从 `h_i^(0)` 预测 `t+1`，再从结合了 `h_i^(0)` 与 `E(t+1)` 嵌入的新隐藏状态 `h_i^(1)` 预测 `t+2`，依此类推。每个深度都是自己的小型 Transformer 块。共享嵌入和共享输出头让参数开销保持适中。在 DeepSeek-V3 的规模下，671B 主模型权重之上增加了 14B MTP 参数。这 2% 的开销同时换来了更密集的训练信号，以及推理时现成的推测解码草稿器。

本课从零构建一个 MTP 模块和 D 深度损失。数学很整齐，实现只有约 150 行。

## 概念

### 顺序式 MTP 配方 <!-- learning-atlas: the-sequential-mtp-recipe -->

DeepSeek-V3 在主模型之上增加 `D` 个 MTP 模块。每个模块 `k`（`k = 1..D`）预测深度为 `k` 的词元，也就是给定截至位置 `i` 的前缀，预测 `t_{i+k}`。

模块 `k` 包含：

- 带有自己的注意力和 MLP 的 Transformer 块 `T_k`。
- 投影矩阵 `M_k`，用于组合前一深度的隐藏状态与下一深度真实词元的嵌入。
- 共享嵌入 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

训练时，对于截至位置 `i` 的前缀，每个深度的隐藏状态为：

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

每个深度的预测为：

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

每个深度都针对真实词元 `t_{i+k}` 计算交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失为：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是较小的权重因子——DeepSeek-V3 在训练开始的 10% 使用 0.3，之后使用 0.1。总训练损失为 `L_main + L_MTP`。

### 为什么是顺序而不是并行

Gloeckle 的原始并行 MTP 有 `D` 个输出头，每个头直接作用于 `h_i^(0)`。每个头从同一个骨干隐藏状态预测 `t_{i+k}`。这种方法可以正常训练，但预测之间没有条件依赖。你不能用 `head_1` 的输出帮助 `head_2`——各个头会并行触发。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 和 `E(t_{i+k})` 构建 `h_i^(k)`。这保留了因果链：要预测 `t_{i+k+1}`，深度 `k+1` 的模块可以看到 `t_{i+k}`。它在结构上与自回归解码器消费自身输出的方式相同，因此 MTP 模块可以直接充当推测解码草稿器。

推理时，把 `h_i^(k-1)` 和草稿词元 `t_{i+k}` 输入模块 `k+1`，得到 `t_{i+k+1}` 的预测，然后重复。这正是 EAGLE 风格的草稿过程，只是把训练好的 MTP 模块当作草稿网络。DeepSeek-V3 报告首个 MTP 模块的接受率超过 80%，加速约 1.8 倍。

### 参数核算

对于隐藏维度为 `h`、词表大小为 `V` 的模型：

- 主模型：数十亿个参数，另有一个大小为 `V * h` 的输出头。
- 共享输出头：复用主模型的头，不增加参数。
- 共享嵌入：复用主模型的嵌入，不增加参数。
- 每个 MTP 模块：
  - 投影 `M_k`：`(2h) * h = 2h^2`。
  - Transformer 块：注意力（MHA 为 `4h^2`）加上 MLP（SwiGLU、比例通常为 8/3，即约 `8h^2`），每块约 `12h^2`。

每个模块的额外参数合计约为 `14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 个模块在纸面上约为 `14 * 7168^2 = 720M` 参数。DeepSeek-V3 报告的数字为 14B，差异主要来自 MTP 模块同样包含专家层 MoE。

### 推测解码收益

预训练期间，MTP 模块会让训练慢约 10%（更多前向计算和额外损失）。收益有两方面：

1. 更密集的训练信号。每个隐藏状态会看到 D+1 个监督目标。DeepSeek-V3 的消融实验在 MMLU、GSM8K、MATH 和 HumanEval 上都观察到稳定的几个百分点提升。

2. 推理时免费获得推测解码草稿器。MTP 模块已经训练成可以预测未来数个词元的网络。把它改作草稿网络后，接受率超过 80%；在这一水平下，N=3 或 N=5 的推测解码可带来 1.8 倍吞吐量。训练阶段增加的 10% 成本在第一次运行推理时就可能收回。

### 与 EAGLE 的关系

EAGLE 在预训练完成后**单独**训练一个小型草稿模型；MTP 则把草稿器直接嵌入预训练。两者的接受率相近，但流程不同：

| 维度 | EAGLE-3 | MTP（DeepSeek-V3） |
|-----------|---------|------------------|
| 训练时机 | 预训练之后 | 预训练期间 |
| 与已有权重向后兼容 | 是 | 否（需要重新训练） |
| 草稿参数 | 1–2 个 Transformer 层 | 1 个 Transformer 块 + 投影 |
| 接受率 | 0.88–0.92 | 深度 1 时 0.80+ |
| 除加速外的收益 | 仅推测解码 | 更密集的训练信号 + 加速 |

## 动手实现

`code/main.py` 端到端构建一个 MTP 模块：共享嵌入、投影层、Transformer 块和共享输出头。随后在一段短的合成序列上计算每深度交叉熵损失，并按组件打印参数量。为了让数字易读，玩具词表只有 32 个词元。

### 第 1 步：共享嵌入表

主模型与每个深度的每个 MTP 模块都使用同一个 `vocab_size x hidden` 表，也就是同一个张量，而非第二份副本。

### 第 2 步：每深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # concat along feature dim, then project down to hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # vector addition stand-in
    projected = matvec(M_k, concat)
    return projected
```

真实的 DeepSeek-V3 会将两个 RMSNorm 向量拼接为 `[2h]`，再用 `h x 2h` 矩阵投影。玩具实现为简洁起见使用向量加法。

### 第 3 步：深度 `k` 的 Transformer 块

它由自注意力和 MLP 组成。玩具实现使用单层线性注意力块和 SwiGLU MLP，在不依赖 numpy 的情况下保持结构清晰。

### 第 4 步：共享输出头

复用主模型的输出投影，得到词表上的 logits。

### 第 5 步：每深度损失

计算 `softmax(logits)` 针对偏移量 `k` 的真实词元的交叉熵，再以 `lambda / D` 因子聚合各深度损失。

### 第 6 步：参数核算

打印总参数量、共享部分（嵌入和输出头）参数量以及每个模块的额外参数量，并显示 MTP 额外参数相对于主模型大小的比例。

## 使用它

MTP 已集成到 DeepSeek-V3（2024 年 12 月）和 DeepSeek-R1 系列中。推理时：

- DeepSeek 自己的服务栈可以直接把 MTP 模块作为推测解码器。
- 截至 2026 年 4 月，vLLM 和 SGLang 都提供了 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了针对 V3 检查点的 MTP 推测解码配置，并测得 1.8 倍加速。

在新的预训练任务中适合使用 MTP 的情况：

- 你控制完整的预训练流水线，希望获得更密集的训练信号。
- 你确定会大规模服务模型，希望免费得到推测解码。
- 隐藏维度至少为 4096。在 1B 规模上，开销可能超过收益。

不适合使用的情况：

- 微调已有的预训练稠密模型，因为 MTP 模块并未训练。
- 想保持干净基线以作对比的研究模型，因为 MTP 会改变架构。

## 练习

1. 运行 `code/main.py`。展示当合成信号增强时，每深度损失单调下降。将合成数据改为固定模式，验证深度 1 和深度 2 的损失都会收敛。

2. 对一个稠密 70B 模型（隐藏维度 8192、80 层、D=1 个 MTP 模块）计算参数开销，并与 DeepSeek-V3 报告的 14B 开销比较。解释 DeepSeek 数字更高的原因：MTP Transformer 块继承了相同的 MoE 结构，增加了每个模块的参数量。

3. 在玩具实现中加入 D=2：增加第二个 MTP 模块，让它接收 `h^(1)` 并预测 `t_{i+2}`。验证联合损失和参数核算符合 DeepSeek 论文的公式 19–21。

4. 切换到并行 MTP（Gloeckle 风格）：在主模型隐藏状态上增加 D 个输出头，每个头预测不同偏移量。在同一个合成信号上比较各深度损失。由于顺序版本会以中间预测为条件，k > 1 时它应产生更低的深度 k 损失。

5. 将训练好的 MTP 模块用作 EAGLE 风格草稿器：在推理时调用模块 k 提议 `t_{i+k}`，再在留出序列上将这些草稿词元与主模型预测比较并测量接受率。如果玩具实现达到 50% 以上，就复现了 MTP 作为草稿器的经验性质。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| MTP 模块 | “额外损失块” | 一个小型 Transformer 块加投影层，用于预测比主模型提前 `k` 个位置的词元 |
| 预测深度 | “偏移多少” | 整数 `k`；模块 `k` 从截至位置 `i` 的前缀预测 `t_{i+k}` |
| 并行 MTP | “Gloeckle 风格” | 在同一个骨干隐藏状态上的 D 个独立头，没有条件链 |
| 顺序式 MTP | “DeepSeek-V3 风格” | 每个模块都以之前深度的隐藏状态和下一词元嵌入为条件，保留因果链 |
| 共享输出头 | “复用主头” | MTP 模块调用主模型的 LM 头，而不是单独的输出投影 |
| 共享嵌入 | “复用主表” | 各处使用同一张词表嵌入表，不复制参数 |
| 投影矩阵 `M_k` | “组合隐藏状态与下一词元” | 一个 `h x 2h` 线性层，将前一隐藏状态和目标词元嵌入折叠为下一深度输入 |
| 联合损失 `L_MTP` | “平均额外损失” | 各深度交叉熵的算术平均，再乘以 `lambda` |
| 深度 1 接受率 | “MTP 草稿有多常正确” | D=1 MTP 模块 top-1 预测与主模型 top-1 预测相同的比例；DeepSeek-V3 为 80%+ |
| Lambda 权重 | “额外损失的重要性” | 每深度缩放因子；DeepSeek-V3 训练初期为 0.3，后期为 0.1 |
