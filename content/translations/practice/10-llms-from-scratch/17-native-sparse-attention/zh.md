# 原生稀疏注意力（DeepSeek NSA）

> 在 64k 个词元的上下文中，注意力会吞掉解码延迟的 70%–80%。各家开源模型团队都在设法解决这个问题。DeepSeek 的 NSA（ACL 2025 最佳论文）是最终脱颖而出的方案：三个并行注意力分支——压缩后的粗粒度词元、选择性保留的细粒度词元，以及用于局部上下文的滑动窗口——再通过一个学习得到的门控进行组合。它与硬件对齐（对内核友好）、原生可训练（在预训练阶段就能工作，而不是在推理时临时外挂），在 64k 解码时速度超过 FlashAttention，同时质量达到甚至超过完整注意力。本课将端到端构建这三个分支，并说明为什么这种稀疏性可以端到端微分。

**类型：** 构建
**语言：** Python（标准库）
**前置课程：** 第 7 阶段 · 第 12 课（KV 缓存、FlashAttention）、第 7 阶段 · 第 15 课（注意力变体）、第 10 阶段 · 第 16 课（差分注意力）
**预计时间：** 约 60 分钟

## 学习目标

- 说出 NSA 注意力的三个分支，以及每个分支捕捉的内容。
- 解释为什么 NSA 是“原生可训练的”，而此前的稀疏注意力方法只能用于推理。
- 根据压缩块大小和选择的 top-k，计算 64k 上下文中 NSA 相比完整注意力节省的计算量。
- 在短小的合成序列上用 Python 标准库实现三个分支的组合，并验证门控权重的行为。

## 问题

序列长度为 N 时，完整注意力每层的时间复杂度为 `O(N^2)`，KV 缓存为 `O(N)`。在 64k 个词元下，计算量和内存带宽的数字都达到灾难级别。NSA 论文给出的理论估算表明：在 64k 时，注意力占总解码延迟的 70%–80%。下游的一切——TTFT、每秒词元数、每百万词元成本——都由注意力成本主导。

稀疏注意力提供了答案。此前的尝试大致分成两类。固定模式稀疏（滑动窗口、步进式、块局部）会丢失信息，在长程召回任务中失败。推理时稀疏（KV 缓存裁剪、H2O、StreamingLLM）被应用于在稠密注意力上预训练的模型，只能获得潜在加速的一小部分，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力（Yuan 等，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）两者兼顾：模型在预训练期间学习稀疏模式，同时将其实现为与内核对齐的算法，在推理时真正兑现计算节省。两年后，NSA 或其直接后继者会成为所有前沿长上下文模型的默认注意力机制。

## 概念

### 三个并行分支

对于每个查询，NSA 会针对 KV 缓存的三种不同视图各运行一次注意力：

1. **压缩分支。** 词元按大小为 `l` 的块分组（通常为 32 或 64）。每个块通过一个小型、经过学习的 MLP 压缩成一个摘要词元。查询会在这些压缩词元上执行注意力，从而获得整个序列的粗粒度视图。

2. **选择分支。** 使用压缩分支的注意力分数，找出与当前查询最相关的 top-k 个块。读取这些块中的细粒度（未压缩）词元，然后让查询关注其中全部词元。可以把压缩分支注意力看作选择过程的路由信号。

3. **滑动窗口分支。** 查询会关注最近的 `W` 个词元（通常为 512），以获取局部上下文。这个分支捕捉结构密集的短程模式（语法、局部指代），这些可能会被另外两个分支遗漏。

三个分支的输出通过一个按位置学习的门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是以查询为输入的小型 MLP 生成的门控权重。它们不必加和为 1——可以独立地给各分支加权。

### 为什么它是“原生可训练的”

选择步骤（top-k 块）是离散的。离散操作会切断梯度流。此前的稀疏注意力工作要么跳过穿过选择步骤的反向传播（限制了训练），要么使用在推理时无法带来真正稀疏性的连续松弛。

NSA 绕开了这个问题：压缩分支注意力本身就是对整个序列执行的可微粗粒度注意力。top-k 操作只是复用压缩分支的最高注意力分数，用来决定加载哪些细粒度块。梯度会穿过压缩分支的分数（这些分数同时影响压缩输出和选择逻辑），而被选块对最终输出的贡献也同样可微。不可微的 `top_k` 操作在前向计算图上相当于无操作——它只控制从内存中加载哪些块。

正因为如此，NSA 可以端到端用于预训练。模型联合学习如何通过三个分支路由信息，形成一种稀疏模式，并在推理时真正带来所承诺的加速。

### 与硬件对齐的内核

NSA 的内核针对现代 GPU 内存层次设计。内核按 GQA 组加载查询（外层循环），按组获取对应的稀疏 KV 块（内层循环），并在 SRAM 上运行注意力。由于每个查询组看到相同的选定块（选择以查询组为单位，而不是以查询头为单位），KV 加载成本可以在整个查询组中摊销。算术强度因此保持在较高水平。

论文报告称，在 64k 解码上，Triton 内核的运行速度比 FlashAttention 快 9 倍，而且随着序列长度增加，加速比还会提高。同时提供前向和反向内核。

### 计算预算

令 `N` 表示序列长度，`l` 表示压缩块大小，`k` 表示 top-k 选择数量，`w` 表示滑动窗口，`b` 表示选定块大小（通常等于 `l`）。

- 压缩分支：每个查询有 `O(N/l)` 个键，因此总计为 `O(N * N / l)`。
- 选择分支：每个查询有 `O(k * b)` 个键，因此总计为 `O(N * k * b)`。
- 滑动分支：每个查询有 `O(w)` 个键，因此总计为 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时，每个查询的成本是 `1000 + 1024 + 512 = 2536 keys`。完整注意力是 `64000 keys`。计算量减少 25 倍。

当 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时，每个查询的成本是 `2000 + 1024 + 512 = 3536 keys`。完整注意力是 `128000 keys`。计算量减少 36 倍。序列越长，收益越大，这正是整个方法的意义所在。

### 如何比较

| 方法 | 可微分 | 实际推理加速 | 长程召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 步进式 / 块稀疏 | 是 | 是 | 部分 |
| KV 裁剪（H2O、StreamingLLM） | 不适用（推理时） | 是 | 部分 |
| MoBA（Moonshot） | 部分 | 是 | 良好 |
| NSA | 是（原生） | 是（64k 时 9 倍） | 与完整注意力相当 |

MoBA（Moonshot，arXiv:2502.13189）与 NSA 同期发布，采用了类似“三个胜过一个”的思路，将 MoE 原则应用于注意力块。对于 2026 年的长上下文预训练，NSA 和 MoBA 是必须了解的两种架构。

## 动手构建

`code/main.py` 在一个短小的合成序列上实现三个分支，并展示：

- 压缩 MLP（为了教学清晰，这里使用简单的均值池化基线；真正的 NSA 使用经过学习的 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 对最后 `w` 个词元执行的滑动窗口注意力。
- 门控组合。
- 与完整注意力进行比较的计算量统计输出。

### 步骤 1：将词元压缩为块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤 2：压缩分支注意力

对查询和压缩键运行 softmax 注意力。压缩分支的分数同时充当 top-k 选择的信号。

### 步骤 3：选择 top-k 块

选出得分最高的 `k` 个压缩块的索引。加载这些块中的原始未压缩词元，并在这些词元上运行注意力。

### 步骤 4：滑动窗口注意力

取最后 `w` 个词元，并对它们运行标准注意力。

### 步骤 5：门控与组合

查询上的一个小型 MLP 会生成三个门控权重。最终输出是三个分支输出的加权和。

### 步骤 6：统计计算量

打印每个分支每个查询关注的键数量，以及总数。将它与 `N`（完整注意力）比较。在一个 1024 词元的合成序列上，若 `l = 32, k = 4, w = 128`，NSA 每个查询会看到 `32 + 128 + 128 = 288` 个键，而完整注意力会看到 1024 个键——每个查询少处理约 3.5 倍的键。

## 使用它

NSA 已经被用于 DeepSeek 自己的长上下文预训练管道。截至 2026 年 4 月，公共推理栈中的集成状态如下：

- **DeepSeek 内部：** 原生支持，已发布权重使用 NSA 或其后继者 DSA（DeepSeek 稀疏注意力）。
- **vLLM：** 正在为 DeepSeek-V3.x 权重开发实验性的 NSA 支持。
- **SGLang：** 已发布 NSA 基准测试；生产路径跟随 vLLM。
- **llama.cpp / CPU：** 不支持；内核分解的开销在 CPU 吞吐量场景下不值得。

何时选择 NSA：

- 目标是 64k 以上上下文、且计算预算充足的预训练或持续训练。
- 推理 DeepSeek 自己的长上下文检查点。其权重原生采用 NSA。

何时不应选择：

- 为已有的稠密注意力预训练模型提供服务。没有持续训练，无法将 NSA 后装进去。
- 上下文短于 16k。三个分支的开销会压过节省的计算量。
- 批大小为 1 的交互式聊天。对延迟敏感的解码确实受益，但只在长上下文下如此。

## 练习

1. 在一个 1024 词元的合成序列上运行 `code/main.py`。在三个预设之间遍历 `(l, k, w)` 并打印计算量。找出这样一个预设：在干草堆找针测试中相对于完整注意力保持 95% 的召回率，同时使每个查询的键数量最低。

2. 将均值池化压缩器替换为一个微型的学习型 MLP（2 层，隐藏层 32）。在一个信号等于块平均值的合成任务上训练它。用留出数据测量相对于均值池化基线的困惑度差距。

3. 实现门控 MLP。它以查询为输入，输出三个标量。证明门控行为合理：对随机查询采用近似均匀的权重；当查询命中很久之前的块时，则大幅提高选择分支的权重。

4. 计算 128k 上下文下启用 NSA 的 70B 模型的 KV 缓存内存预算。KV 头数为 8，头维度为 128，使用 BF16。将其与完整注意力以及 MLA（第 10 阶段 · 第 14 课给出了 MLA 的数字）比较。找出 NSA 细粒度分支的 KV 缓存等于完整注意力的序列长度。

5. 阅读 NSA 论文第 4 节（arXiv:2502.11089），用三句话解释：为什么复用压缩分支的注意力分数进行 top-k 选择，而不是另算一个路由分数。将答案与梯度流联系起来。

## 关键术语

| 术语 | 人们怎么说 | 它实际指什么 |
|------|------------|--------------|
| 压缩分支 | “粗粒度视图” | 对块平均后的键执行注意力，为每个查询提供包含 O(N/l) 个键的全局上下文 |
| 选择分支 | “Top-k 块” | 对压缩分支分数最高的 `k` 个块执行细粒度注意力 |
| 滑动窗口 | “局部上下文” | 关注最后 `W` 个词元的注意力，用于捕捉短程模式 |
| 原生可训练性 | “开启稀疏性进行预训练” | 稀疏模式在预训练期间学习得到，而不是在推理时临时外挂 |
| 压缩块大小 l | “粗粒度视图的分组大小” | 合并为一个摘要的词元数量；通常为 32–64 |
| Top-k | “保留的块” | 会读取其未压缩词元的压缩块数量；通常为 16 |
| 滑动窗口 W | “局部注意力半径” | 通常为 512；更短会损害局部连贯性，更长则浪费计算量 |
| 分支门控 | “如何混合三个分支” | 按位置生成的 MLP 输出，用于给三个分支的贡献加权 |
| 硬件对齐 | “对内核友好的稀疏性” | 经过选择的稀疏模式，使实际 GPU 内核能够达到理论加速 |
| DSA | “NSA 的后继者” | DeepSeek 稀疏注意力，DeepSeek 系列中继 NSA 出现的架构 |
