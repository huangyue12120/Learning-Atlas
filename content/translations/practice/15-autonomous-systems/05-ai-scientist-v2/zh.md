# AI Scientist v2——研讨会级自主研究

> Sakana 的 AI Scientist v2（Yamada 等，arXiv:2504.08066）运行完整研究循环：假设、代码、实验、图表、写作、投稿。它是首个让生成论文通过 ICLR 2025 研讨会同行评审的系统。独立评估（Beel 等）发现，42% 的实验因编码错误而失败，文献综述也常把已确立概念误标为新颖概念。Sakana 自己的文档警告，该代码库会执行 LLM 编写的代码，建议使用 Docker 隔离。这幅图景的两半都是本课的要点。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具实现）
**前置要求：** 第 15 阶段 · 03（AlphaEvolve）、第 15 阶段 · 04（DGM）
**用时：** 约 60 分钟

## 问题所在

研究是开放式任务。与 AlphaEvolve 的算法搜索或 DGM 受基准约束的自我修改不同，研究结果没有机器可检验的正确性标准。论文由审稿人判断，而不是单元测试。这让循环更难闭合；一旦闭合，也更有价值，因为复合式进展存在于研究中。

AI Scientist v1（Sakana，2024）从人类编写的模板出发，从而闭合了这个循环。LLM 在固定脚手架内填充实验。AI Scientist v2（Yamada 等，2025）利用带视觉语言模型批评循环的智能体树搜索，移除了模板要求。系统生成想法、实现实验、产出图表、撰写论文，并根据审稿反馈迭代。

同行评审结论是：一篇由 v2 生成的论文被 ICLR 2025 研讨会接收（且已披露）。独立评估结论是：该系统还远不可靠。这两点都是真的。

## 核心概念

### 架构

1. **想法生成。** LLM 根据主题和既有文献提出研究想法。v1 使用模板；v2 在假设空间上使用智能体搜索。
2. **新颖性检查。** 文献检索步骤检查该想法是否已被发表。这一步正是 Beel 等评估发现误标的地方——已确立的方法常被分类为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败会反馈至重试循环。在 Beel 等的测量中，这一阶段有 42% 的实验因编码错误而失败。
5. **图表生成。** 视觉语言模型读取生成图表，并将其改写得更清晰。v2 新增了这项技术。
6. **写作。** LLM 起草论文，并与内部审稿人迭代。
7. **可选：投稿。** 将论文投给一个发表场所。

### 研讨会录用结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 研讨会的同行评审。作者向项目委员会披露了论文的来源。这次录用是一个数据点，不是声称系统“会做研究”的许可证。

重要背景是：研讨会论文的门槛低于主会论文。同行评审有噪声；在任何一天，只有一小部分投稿会被接收。一次成功是概念验证，不是可靠性声明。2026 年 Nature 论文记录了端到端循环，且本身由人类研究者共同署名；它并不是“系统写了一篇 Nature 论文”。

### 独立评估发现了什么

Beel 等（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误而失败（错误导入、形状不匹配、未定义变量）。重试循环捕获了一部分，但没有捕获全部。
- **新颖性误标。** 文献检索步骤常把已确立的概念标为新颖。这相当于研究中的幻觉。
- **展示质量差距。** 视觉语言图表批评能产生发表级视觉效果，却掩盖了底层实验弱点。

最后一项是本阶段的重要发现。一个能生成有说服力输出、却未做出有说服力研究的系统，比明显失败的系统更危险，而不是更安全。评估必须触及底层主张，不能止步于图表。

### 沙箱逃逸顾虑 <!-- learning-atlas: the-sandbox-escape-concern -->

Sakana 自己的仓库 README 警告：

> 由于该软件会执行 LLM 生成的代码，我们无法保证安全。它存在危险包、未受控制的网络访问和生成非预期进程的风险。使用风险自担，并考虑 Docker 隔离。

未验证领域中的自主性按这种方式运行：LLM 写代码，代码再运行；进程可以执行沙箱允许的任何动作。若没有硬性限制文件系统、网络和进程动作的沙箱，任何自我导向的研究智能体都可以窃取数据、耗尽算力或重写自身。

AlphaEvolve 的沙箱情况更容易，因为它的评估器很严密。AI Scientist v2 的循环运行开放式代码，服务开放式目标。因此，它需要更强的隔离（Docker 是最低要求；更推荐 seccomp / gVisor），以及在每次投稿离开系统之前进行人工审阅。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准 | 受评估器严谨度约束 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、误标、润色掩盖弱点 |

v2 在三者中拥有最弱的自动评估器、最宽的输出面和通向公开产物的最短路径。运行控制（沙箱、审阅、披露）承担了绝大部分安全工作。

## 实际运行

`code/main.py` 将 v2 循环模拟为一个状态机：想法 → 新颖性检查 → 实验 → 图表 → 写作 → 审阅 → 接收或迭代。每个状态均有从 Beel 等发现中提取的可配置失败概率。将模拟器运行 N 个循环，并统计：

- 有多少想法到达投稿。
- 有多少投稿带有被润色论文隐藏的关键实验缺陷。
- 重试预算如何在质量与产出之间权衡。

## 交付物

`outputs/skill-ai-scientist-sandbox-review.md` 是一个两道闸门的审阅清单，用于审查研究循环智能体生成的任何内容在离开沙箱前的状态。

## 练习

1. 以默认参数运行 `code/main.py`。有多少比例的循环运行产生“干净”论文？有多少比例产生了图表批评润色掩盖掉的实验失败缺陷？

2. 默认值已使用 Beel 等的 42% / 25%。分别使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 和 `--experiment-failure 0.60 --novelty-mislabel 0.40` 重新运行。两次运行间，“润色却有缺陷”的比例如何变化？

3. 阅读 Sakana AI Scientist v2 仓库 README 中关于沙箱要求的内容。除了 Docker 外，为多日自治运行额外施加哪两项限制？

4. 阅读 Beel 等第 4 节有关展示质量差距的内容。设计一个额外评估器，以捕获看起来精美却在实验上有缺陷的论文。

5. 为研究智能体输出提出一种比“博士逐篇阅读论文”更可扩展的人类审阅协议。指出瓶颈，并围绕它设计。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|---|---|---|
| AI Scientist v1 | “Sakana 的模板化研究智能体” | 在固定脚手架中填充实验 |
| AI Scientist v2 | “无模板研究智能体” | 带 VLM 图表批评的智能体树搜索 |
| 智能体树搜索 | “分支式研究智能体” | 并行扩展多个实验计划；由内部批评器剪枝 |
| 视觉语言批评 | “VLM 润色图表” | 多模态模型读取图表并将其改写得更清晰 |
| 文献检索 | “新颖性检查” | 搜索先前工作以确认想法新颖性——已有误标记录 |
| 润色掩盖 | “漂亮论文，破碎研究” | 展示质量超过实验质量，从而隐藏弱点 |
| 沙箱逃逸 | “LLM 代码逃出限制” | 智能体执行的代码做了循环设计者未打算的事 |
