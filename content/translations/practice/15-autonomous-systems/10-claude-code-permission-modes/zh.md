# 自治智能体的权限模式

> 权限阶梯——从“审阅每个动作”到“批准一切”的分级自治级别——规定了智能体可以在不询问的情况下做什么。作为本课案例的 Claude Code 提供六种模式：`plan` 在每个动作前询问，`default`（界面标为“Manual”）只对有风险的动作询问，`acceptEdits` 自动批准文件写入但仍确认 shell 执行，`bypassPermissions` 则批准一切。自动模式（`auto` 权限模式）用独立分类器模型替代逐动作批准：它在每个动作运行前审查，并阻止超出请求范围的升级行为。`max_turns` 和 `max_budget_usd` 强制实施动作预算。`auto` 是否可用取决于套餐、组织启用状态、模型和提供方——Anthropic 也明确指出，分类器本身并不足够。

**类型：** 学习
**语言：** Python（标准库，双阶段分类器模拟器）
**前置要求：** 第 15 阶段 · 01（长时程智能体）、第 15 阶段 · 09（编程智能体全景）
**用时：** 约 45 分钟

## 问题所在

在你的机器上运行的自治编程智能体属于不同的安全类别。攻击面是智能体能触达的一切——文件系统、网络、凭据、剪贴板、任何浏览器标签页、任何已打开的终端。Bruce Schneier 等人已公开指出：计算机使用智能体不是聊天机器人的“功能更新”，而是拥有新型风险画像的一种新工具。

Claude Code 的权限系统是 Anthropic 的回答。它不是一个“自治 / 非自治”的开关，而是跨越能力阶梯的六种模式：plan → default → acceptEdits → … → bypassPermissions。每种模式都在速度与每动作审阅之间做不同权衡。自动模式（2026 年 3 月）加入独立分类器模型，将批准移出用户关键路径：它在每个动作前审查，并阻止超出请求范围的升级行为。

工程问题是：该系统能捕获什么，会遗漏什么，以及一个给定任务实际配得上哪种模式？

## 核心概念

### 六种权限模式

| 模式 | 行为 | 使用时机 |
|---|---|---|
| `plan` | 智能体提出计划；用户批准整个计划；每个动作执行前都经过审阅 | 不熟悉的任务；接近生产的代码；首次在一个仓库上使用智能体 |
| `default` | 界面标为“Manual”。智能体运行动作；对任何“有风险”动作（shell 执行、破坏性操作、网络调用）提示用户 | 大多数交互式编程会话 |
| `acceptEdits` | 文件写入自动批准；shell 执行和网络调用仍会提示 | 跨多个文件的重构 |
| `auto` | 独立分类器模型在每个动作运行前审查；阻止超出请求的升级行为 | 受约束工作区中的长时程无人值守运行 |
| `dontAsk` | 从不提示；没有被权限规则预批准的动作会被拒绝 | 临时沙箱、CI 作业、研究脚本 |
| `bypassPermissions` | 批准一切 | 文档称“仅在你愿意丢弃的临时容器中使用” |

（上述名称匹配公开 Claude Code 文档；界面将 `default` 标为“Manual”。）

### 用一页理解自动模式

自动模式（2026 年 3 月 24 日推出）是第一个将逐动作批准委托给模型的权限模式。结构如下：

1. **独立分类器模型。** 在每个拟议动作运行前审查，依据已声明任务和会话当前状态判断，并阻止超出请求范围的升级行为。被阻止的动作回退给用户。
2. **受限可用性。** 是否提供 `auto` 取决于套餐、组织启用状态、模型和提供方。

分类器旁还有预算控制：

- `max_turns` —— 会话中的总迭代次数。
- `max_budget_usd` —— 中止会话的美元上限。
- 每种工具的动作次数限制（例如不超过 N 次 `WebFetch` 调用）。

### 系统能捕获什么

- 工具输入中直接的提示词注入，其中注入指令映射到已知的高风险动作形状。
- 重复工具循环——分类器可以看到动作 N+1 与动作 N 几乎相同，且连续重复五次。
- 在原本仅编辑文件的会话中，明显超出范围的 shell 命令。

### 系统可能遗漏什么

- **细微的提示词注入。** 它会调制行为，却不产生单个被标记的动作。间接提示词注入不是一个可被完全修补的漏洞（OpenAI preparedness 负责人，2025 年，关于浏览器智能体——见第 11 课）。
- **语义层不当行为。** 每个单独动作看起来都安全，而组合起来的轨迹有害。分类器判断动作，不会重新推导用户意图。
- **通过合法渠道外泄。** 将数据写入你拥有的文件，再 `git push` 到公共仓库，是一串允许动作，其组合才是问题。

### 研究预览的定位

Anthropic 将自动模式作为研究预览发布。文档明确：分类器是一层，而非解决方案；使用者应把自动模式与预算、允许列表、隔离工作区和轨迹审计（第 12–16 课）结合。预览定位也反映已记录的评估—部署差距（第 1 课）——通过离线评估的分类器，在用户上下文模糊的真实会话中可能表现不同。

### 这个阶梯在工作流中的位置 <!-- learning-atlas: where-this-ladder-lives-in-your-workflow -->

- 不熟悉的任务：从 `plan` 开始。阅读计划比回滚一次糟糕运行更便宜。
- 已知重构：`acceptEdits` 可省去大量确认点击。
- 无人值守的后台运行：仅在已测量爆炸半径的工作区中使用 `auto`（没有凭据、没有生产挂载、没有未经你选择的外连）。
- 临时容器：仅当容器及其凭据均可丢弃时，`dontAsk` / `bypassPermissions` 才可接受。

## 实际运行

`code/main.py` 将动作审查分类器模拟为双阶段流水线——这是一种教学简化；真实 `auto` 模式由独立分类器模型支持，并非有文档说明的双阶段契约。第 1 阶段对拟议动作运行廉价的关键词规则；第 2 阶段使用较慢的多规则审阅器。驱动程序送入一条简短合成轨迹（安全动作、一次提示词注入尝试、一个重复循环），展示分类器在何处捕获、何处遗漏。

## 交付物

`outputs/skill-permission-mode-picker.md` 将任务说明匹配到正确权限模式、预算上限和所需隔离。

## 练习

1. 运行 `code/main.py`。哪类合成动作从不被第 1 阶段标记、却总被第 2 阶段捕获？哪类两者都捕获不到？

2. 扩展第 1 阶段规则集，捕获一个具体的已知恶意形状（例如 `curl $ATTACKER/exfil`）。在良性动作样本上测量假阳性率。

3. 阅读 Anthropic 的“How the agent loop works”文档。列出智能体在 `default` 模式下默认触及的所有外部状态。若要无人值守地运行 `auto`，哪些需要单独设置闸门？

4. 设计一次 24 小时无人值守运行的预算：`max_turns`、`max_budget_usd`、每工具上限、允许列表。说明每个数值的理由。

5. 描述一条轨迹：分类器批准了每一个单独动作，组合行为却失配。（第 14 课介绍紧急停止开关和金丝雀 token 如何应对。）

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|---|---|---|
| 权限模式 | “智能体能做多少事” | 控制逐动作批准的六种命名策略之一 |
| plan 模式 | “任何事之前都问” | 智能体写计划；用户在执行前批准 |
| acceptEdits | “让它写文件” | 文件写入自动批准；shell 执行仍会提示 |
| auto | “自动批准” | 独立分类器审查每个动作；阻止超出请求的升级 |
| bypassPermissions | “完全 YOLO” | 批准一切；为临时容器设计 |
| 第 1 阶段（模拟器） | “快速关键词检查” | `code/main.py` 中对拟议动作的廉价规则 |
| 第 2 阶段（模拟器） | “深度审阅” | `code/main.py` 中针对已标记动作的较慢多规则审阅器 |
| 研究预览 | “不是 GA” | Anthropic 对失败模式仍在被映射的功能所作的定位 |
