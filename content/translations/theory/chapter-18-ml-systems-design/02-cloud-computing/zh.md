# 云计算

*云计算为机器学习（ML）工作负载提供按需基础设施，不必自行购买和维护硬件。本文介绍云服务模型、主要云厂商、容器与 Kubernetes、存储、云网络、无服务器计算、成本管理和基础设施即代码。*

- 训练前沿模型可能需要大量 GPU 和长时间运行。云计算让团队按需租用硬件，在训练期间扩容、在推理负载下降时缩容，并按实际使用计费。云基础设施是构建笔记本之外的机器学习系统时需要理解的一部分。

## 云服务模型

![云服务分层：IaaS 提供的控制权最多，SaaS 提供的控制权最少](../images/cloud_service_layers.svg)

- 云服务按服务商负责管理的范围分层：

| 模型 | 用户管理 | 服务商管理 | 示例 |
|-------|-----------|-----------------|---------|
| **IaaS**（基础设施即服务） | 操作系统、运行时、应用 | 硬件、虚拟化、网络 | AWS EC2、GCP Compute Engine |
| **PaaS**（平台即服务） | 应用、数据 | 操作系统、运行时、扩缩容、补丁 | AWS SageMaker、GCP Vertex AI |
| **SaaS**（软件即服务） | 无需管理基础设施，直接使用 | 服务本身及其底层系统 | OpenAI API、Weights & Biases |
| **FaaS**（函数即服务） | 单个函数 | 函数运行所需的其余部分 | AWS Lambda、GCP Cloud Functions |

- **机器学习场景**：团队常混合使用多种模型。自定义训练可选择可完全控制 GPU 实例的 IaaS；托管训练和服务可选择由平台编排的 PaaS（如 SageMaker、Vertex AI）；实验跟踪或模型 API 等工具可使用 SaaS。

## 主要云厂商

- 原文称 AWS 是最大的云服务商，并估计 AWS、GCP、Azure 的市场份额分别约为 32%、11%、23%；但未注明报告来源和统计年份。市场份额会随统计口径和时间变化，不应当作当前数据。

### AWS（Amazon Web Services）

- AWS 是大型云服务商之一。常见机器学习服务包括：
    - **EC2**：虚拟机。GPU 实例包括 p4d（A100）、p5（H100）和 g5（A10G，可用于推理）。具体规格与区域供应情况会变动。
    - **S3**：对象存储，常用于保存数据集和模型权重。容量可按需扩展；每 GB 每月约 0.023 美元是特定存储类别和区域的示例价格。
    - **SageMaker**：托管机器学习平台，提供训练、超参数搜索、部署和监控功能。
    - **EKS**：托管 Kubernetes 服务。
    - **Lambda**：无服务器函数，适用于数据预处理和编排；通常不提供 GPU 执行环境。

### GCP（Google Cloud Platform）

- Google 的云平台提供以下服务：
    - **Compute Engine**：虚拟机，可按区域和供应情况选择 A100、H100 等 GPU；也可使用 **TPU VM** 访问 TPU。
    - **GCS**：对象存储，功能类似 S3。
    - **Vertex AI**：托管机器学习平台，提供 JAX 和 TPU 等工具的集成支持。
    - **GKE**：托管 Kubernetes 服务。Google 发起了 Kubernetes 项目；“最成熟”属于评价，具体能力需按功能和版本比较。
    - **Cloud TPU**：GCP 提供的 TPU 服务；v5e、v5p 等代际面向不同规模和工作负载，供应情况因区域而异。

### Azure（Microsoft）

- Microsoft 的云平台包括：
    - **Azure VM**：虚拟机，可按供应情况选择 A100、H100 等 GPU 实例。
    - **Azure Blob Storage**：对象存储。
    - **Azure Machine Learning**：托管机器学习平台。
    - **AKS**：托管 Kubernetes 服务。
    - **Azure OpenAI Service**：通过 Azure API 访问受支持的 OpenAI 模型；模型、区域和访问条件以服务目录为准。

## 容器和 Kubernetes

- 第 13 章（操作系统）从概念上介绍了 Docker 容器与 Kubernetes，第 15 章（部署）介绍了实践。本节聚焦云环境中的常见模式：

### 面向机器学习的 Kubernetes

- **Kubernetes（K8s）**可在集群中编排容器。常见概念包括：
    - **Pod**：最小可部署单元，可包含一个或多个共享网络和存储卷的容器。例如，模型服务 Pod 可同时运行模型服务器和采集指标的 sidecar 容器。
    - **Deployment**：管理一组相同的 Pod，并声明期望副本数。Pod 故障后，控制器会尝试创建替代实例。
    - **Service**：为一组 Pod 提供稳定网络入口，并按规则转发到可用 Pod。ClusterIP 用于集群内部，NodePort 通过节点端口暴露，LoadBalancer 通常会配置云负载均衡器。
    - **StatefulSet**：用于需要稳定身份或持久化存储的 Pod，例如数据库和部分分布式训练工作进程。
    - **DaemonSet**：在符合选择条件的每个节点上运行 Pod，常用于监控代理（如 Prometheus node exporter）、日志采集器（如 Fluentd）或 GPU 设备插件。
- **Kubernetes 中的 GPU 调度**：NVIDIA device plugin 可把 GPU 暴露为 Kubernetes 资源，Pod 可声明所需数量：

```yaml
resources:
  limits:
    nvidia.com/gpu: 2  # this pod needs 2 GPUs
```

- 调度器会尝试把 Pod 放到有足够可用 GPU 资源的节点上。这是云端机器学习平台为训练和推理任务分配 GPU 的一种方式；实际调度还受节点类型、驱动、拓扑和配额限制。

### 自动扩缩容

- **水平 Pod 自动扩缩器（HPA）**：根据 CPU 使用率、请求速率或队列深度等指标调整 Pod 副本数。GPU 利用率等自定义指标需先正确采集并接入。
- **集群自动扩缩器**：若因节点不足而无法调度 Pod，可向云厂商申请新虚拟机；节点空闲时，也可驱逐工作负载并释放节点。新节点启动需要时间，扩容不是即时完成。
- **KEDA**（Kubernetes 事件驱动自动扩缩容）：根据 Kafka 队列长度或 HTTP 请求量等外部事件调整工作负载副本数。用于推理服务时，可在队列增长时扩容、负载下降时缩容，但受冷启动和 GPU 供应时间影响。

## 存储

| 类型 | 特点 | 用途 | 示例 |
|------|----------------|----------|---------|
| **块存储** | 通常挂载给一台虚拟机，延迟较低 | 系统盘、数据库 | AWS EBS、GCP Persistent Disk |
| **对象存储** | 可扩展的对象容量，通过 API 访问 | 数据集、模型权重、日志 | AWS S3、GCS、Azure Blob |
| **文件存储** | 多台虚拟机可共享，提供 POSIX 风格文件接口 | 共享训练数据 | AWS EFS、GCP Filestore、NFS |
| **数据湖** | 原始数据按读取时 schema 解释 | 分析、特征工程 | Delta Lake、Iceberg、Hudi |

- **机器学习训练数据**通常保存在 S3 或 GCS 等对象存储中，训练时再读取到内存。随机打乱数据时可考虑：训练前下载到本地 SSD、使用 Lustre 或 FSx 等高吞吐文件系统，或使用能流式读取和缓存的库（如 WebDataset、FFCV）。具体选择取决于数据规模、网络和访问模式。
- **模型权重**可存放在带版本管理的对象存储中。70B 参数模型的 FP16 原始权重约 140 GB（十进制）。假设持续传输速度为 1 GB/s，理论传输时间约 140 秒（约 2.3 分钟）；实际速度取决于网络、并行读取和存储配置。将权重缓存到本地 SSD 可缩短冷启动时间。

## 云网络

- **VPC（虚拟私有云）**：云环境中的隔离网络，虚拟机、数据库和服务可通过其内部网络通信。外部流量通常经负载均衡器或网关进入。
- **子网**：把 VPC 划分为多个网段。公共子网可配置互联网入口，例如放置 API 服务器；私有子网通常用于数据库和 GPU worker，并通过受控路径通信。这是最小权限网络设计的一种做法。
- **安全组**（AWS）或**防火墙规则**（GCP）：控制允许通过的网络流量。例如，开放来自任意地址的 HTTP 80 端口，只允许指定 IP 通过 SSH 22 端口，其余流量拒绝。配置错误是云资源暴露的常见原因之一。
- **服务网格**（Istio、Envoy 等）可管理 Kubernetes 服务间通信，并按配置提供双向 TLS（mTLS）、流量路由（例如将 10% 流量送往新模型）、重试、超时、熔断和可观测性功能。具体能力和默认配置因实现而异。

## 无服务器计算

- **无服务器计算**（如 AWS Lambda、GCP Cloud Functions）由用户上传函数，云平台在触发时运行。用户无需直接管理服务器，平台负责扩缩容；通常按调用次数和计算时间计费。每百万次调用约 0.20 美元只是部分平台的请求费用示例，不包括计算时间及其他费用。
- **冷启动**：函数闲置一段时间后首次调用，平台可能需要创建运行环境并加载代码，因此比后续调用慢。原文给出的 0.5–5 秒是示例范围，实际延迟依运行时、程序包大小和平台而异。
- **机器学习用途**：无服务器函数可用于图像缩放等预处理、模型输出格式化等后处理、流水线编排，以及可容忍冷启动的小模型推理。
- 多数函数式无服务器平台并不提供 GPU，也会限制单次运行时间；例如 AWS Lambda 的单次执行最长为 15 分钟。长时间训练、严格低延迟 GPU 推理和需持久状态的服务通常需要其他执行环境。无服务器函数不应依赖不同调用之间保留本地状态。

## 成本管理

- 云费用是机器学习团队的重要运维成本。单张 H100 实例每小时约 8 美元、64 GPU 训练集群每小时约 500 美元，是特定价格假设下的估算；连续运行一个月的费用可达数十万美元。实际价格随区域、实例构成、折扣、利用率和租赁方式变化。
- **抢占式/可抢占实例**：云平台以折扣提供可被回收的闲置容量，示例折扣为 60–90%；服务商可能提前 30 秒到 2 分钟通知回收。可用于定期保存检查点的容错训练、批量推理和数据处理；交互式服务需设计好中断和恢复策略。
- **预留实例**：承诺使用 1–3 年以换取折扣，示例为 30–60%。适合负载稳定、能预测基础用量的服务；实际折扣和取消条件依合同而异。
- **自动扩缩容**：高峰扩容、夜间或周末缩容。若服务白天需要 10 张 GPU、夜间需要 2 张，节省比例取决于两种负载各持续多久及扩缩容开销，不能直接保证节省 60%。
- **按需选型**：若 7B 模型可在 A10G 上满足目标，就不一定要租 H100；可用性能分析（第 16 章）比较符合延迟、显存和吞吐要求的设备。
- **存储费用**：对象存储的单价通常较低，但历史检查点会不断累积。若每个实验保存 100 个、每个 10 GB 的检查点，共 50 个实验，则约占 50 TB；按每 GB 每月 0.023 美元计算，约为每月 1150 美元。应设置生命周期策略清理过期文件，并按实际区域与存储类别估价。

## 多区域部署

- 面向全球用户的机器学习系统若只部署在一个区域，远距离用户可能有更高网络延迟；例如东京用户访问美国服务器的往返延迟可能约 150 ms，实际取决于区域、运营商和网络路径。单一区域故障也可能导致服务整体不可用。
- **多区域模式**：
    - **主动—被动**：主区域处理流量，备用区域同步或异步复制数据并保持待命。主区域故障后通过 DNS 或流量管理服务切换；恢复时间可能从几十秒到数分钟，取决于检测、DNS 缓存和应用恢复。
    - **主动—主动**：多个区域同时处理流量，用户通常被路由到较近区域。数据可以同步或异步复制；发生单区域故障时，系统可将流量转到其他区域，但只有在容量、状态和故障切换均准备好的情况下才能减少停机。
- **数据复制**是关键难点之一。模型权重通常容易复制到各区域对象存储；特征库需要在可接受的数据陈旧度下复制。用户数据还可能受**数据驻留**法规或合同约束；例如，欧盟个人数据受 GDPR 等规则约束，但不能笼统理解为所有欧洲用户数据必须仅存放在欧洲。
- 下表是原文标注为约 2026 年的 GPU 云价格示例；价格随区域、按需/预留方式、折扣和库存变化：

| GPU | AWS | GCP | Azure | 常见用途 |
|-----|-----|-----|-------|-------------|
| A10G（24 GB） | 约 $1.00/小时（g5） | 约 $0.90/小时 | 约 $0.90/小时 | 小模型推理 |
| A100（80 GB） | 约 $4.10/小时（p4d） | 约 $3.70/小时 | 约 $3.40/小时 | 训练、大模型推理 |
| H100（80 GB） | 约 $8.00/小时（p5） | 约 $7.50/小时 | 约 $7.00/小时 | 大规模训练 |
| TPU v5e | 不适用 | 约 $1.20/小时 | 不适用 | 大规模 JAX 训练 |

- 抢占式或可抢占实例相对按需价格常有折扣；原文分别给出 60–90% 和 60–70% 的估算区间，差异反映价格随区域、实例和容量变化，实际折扣需以当时报价为准。

## 基础设施即代码

- **基础设施即代码（IaC）**用版本控制的配置文件描述虚拟机、网络、数据库和 Kubernetes 集群等基础设施。与在控制台逐项点击不同，IaC 工具读取期望状态并自动创建或修改资源。
- **Terraform**（HashiCorp）是常见的 IaC 工具之一，支持多家云服务商。它采用声明式配置：用户描述目标状态，Terraform 计算需要创建、修改或删除的资源。

```hcl
# main.tf — create a GPU VM for inference
resource "aws_instance" "model_server" {
  ami           = "ami-0abcdef1234567890"  # Deep Learning AMI
  instance_type = "g5.xlarge"               # A10G GPU

  tags = {
    Name = "model-server-prod"
  }
}

resource "aws_s3_bucket" "model_weights" {
  bucket = "my-model-weights-prod"

  versioning {
    enabled = true
  }
}
```

```bash
terraform init      # download provider plugins
terraform plan      # show what will change
terraform apply     # create the infrastructure
terraform destroy   # tear it all down
```

- **IaC 的作用**包括：可从代码重建基础设施、通过 Git 历史审计变更、在灾难后于其他区域重建环境，以及让开发、预发布和生产环境复用模板并采用不同参数。
- **Pulumi**：与 Terraform 类似，但允许用 Python、TypeScript、Go 等通用编程语言定义基础设施；当配置逻辑包含较复杂的条件、循环或动态参数时可能更方便。
