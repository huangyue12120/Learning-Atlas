# 操作系统

*操作系统是硬件和应用程序之间的软件层，管理资源、提供抽象并实现隔离。本文件涵盖了操作系统的作用、进程、线程、CPU调度、内存管理、文件系统以及系统调用等内容。*

- 没有操作系统的计算机就像没有厨师的厨房：原料（硬件）在，但没有人协调谁使用炉灶、在哪里放盘子或如何防止两个人拿同一个刀叉。**操作系统就是那个协调者。**

- 对于机器学习从业者来说，操作系统概念解释了为什么 `nvidia-smi` 显示进程的 GPU 内存使用情况，为什么训练时会出现“内存不足”的错误，为什么 `fork()` 复制了你的 Python 进程，以及为什么 Docker 容器提供了隔离环境。

## 操作系统的作用

- 操作系统有三个核心责任：

    - **抽象**：将硬件复杂性隐藏在干净的接口后面。程序读写“文件”而不知道底层存储是 SSD、HDD 还是网络驱动器。它们分配“内存”而不管理物理 RAM 芯片。它们运行在“CPU”上而不担心中断和缓存一致性。

    - **资源管理**：多个程序共享 CPU、内存、硬盘和网络。操作系统决定谁得到什么、何时以及持续多长时间。公平、高效的分配策略保持系统响应迅速。

    - **隔离和保护**：程序必须相互独立。你的网页浏览器中的一个 bug 不应导致内核崩溃。一个恶意程序不应读取另一个程序的密码。操作系统通过硬件支持（特权级别、虚拟内存）来 enforce边界。

## 进程

- **进程**是正在运行的程序。它是操作系统的基本工作单元。每个进程都有：

    - **代码**（程序指令，只读）。
    - **数据**（全局变量、堆分配）。
    - **栈**（函数调用帧、局部变量）。
    - **状态**（寄存器值、程序计数器、打开文件等）。

- **进程控制块 (PCB)** 是操作系统跟踪进程的数据结构。它存储进程 ID (PID)、状态、程序计数器、寄存器内容、内存映射、打开文件描述符和调度优先级。当操作系统从一个进程切换到另一个进程时，它保存当前进程的状态到其 PCB 并加载下一个进程的状态。这称为**上下文切换**。

- 上下文切换昂贵：保存和恢复寄存器、刷新缓存和无效 TLB 入口需要微秒级时间。在运行数千个进程的系统上，这种开销可能相当显著。这就是为什么基于请求的单进程架构（如旧版 Apache）被基于线程或事件驱动的架构所取代。

- 在 Unix 中，进程创建使用 `fork()` 和 `exec()`:

    - `fork()` 创建一个 **副本** 当前进程。子进程得到父进程的内存、文件描述符和状态的副本。两个进程从同一个点继续执行，但 `fork()` 返回 0 在子进程中，而父进程中返回子进程的 PID.

    - `exec()` 替换当前进程的代码为一个新的程序。在 `fork()` 后，子进程通常调用 `exec()` 运行不同的程序.

    - 这种 fork-then-exec 模型很优雅：创建新进程（fork）和加载新程序（exec）是两个独立的操作，可以分别独立定制。在 fork 和 exec 之间，子进程可以重定向 I/O、更改环境变量或降权.

![进程状态转换：新建→就绪→运行→阻塞/终止，包含抢占和I/O等待。](../images/process_states.svg)


- **进程状态**：一个进程处于几种状态之一：
    - **运行**：当前正在 CPU 核心上执行。
    - **就绪**（等待）：等待 CPU 核心（可运行但尚未调度）。
    - **阻塞（等待）**：无法继续，直到某些事件发生（I/O 完成、锁获取、定时器超时）。
    - **终止**（完成）：执行完毕，等待父进程收集其退出状态。

## 线程

- **线程** 是一个进程内的轻量级执行单元。所有进程中的线程共享相同的代码、数据和堆，但每个线程都有自己的栈和寄存器状态。

- 优势：线程共享内存，因此通信速度快（只需读写共享变量）。进程需要通过管道、套接字或共享内存映射进行进程间通信，这较慢且复杂得多。

- 劣势：共享内存危险。两个线程同时写入同一个变量可能会导致 **竞态条件**（结果取决于哪个线程先运行）。这促使我们进行同步，覆盖在文件 4 中。

- **内核线程** 由操作系统调度器管理。每个线程独立地被调度到 CPU 核心上。创建和切换内核线程涉及系统调用，与（但略小于）进程上下文切换的开销相似。

- **用户线程**（绿色线程）由用户空间中的运行时库管理，对操作系统来说是不可见的。它们创建和切换更便宜（不需要系统调用），但一个阻塞的用户线程会阻止整个进程中的所有线程（因为操作系统只看到一个内核线程）。

- 现代系统使用 **混合模型**：许多用户线程映射到较少的内核线程上（M:N 多线程）。Go 的 goroutines 和 Erlang 的进程是用户级线程，由语言运行时在 OS 线程上调度。

- **线程池**预先创建固定数量的线程，这些线程等待任务。当一个任务到达时，它被分配给空闲的线程。这避免了为每个任务创建和销毁线程的开销。Web服务器、数据库引擎和机器学习推理服务器都使用线程池。

## CPU调度

- **调度器**决定在每个时刻哪个进程或线程运行在哪个CPU核心上。目标是：最大化CPU利用率、最小化响应时间（对于交互任务）、最大化吞吐量（对于批处理任务）和确保公平性。

- **先到先服务（FCFS）**：按到达顺序的顺序运行进程。简单但存在** convoy效应**：一个长时间运行的进程会阻塞所有较短的进程在其后面。

- **最短作业优先（SJF）**：首先运行最短的进程。理论上可以最小化平均等待时间，但需要在知道工作量的情况下进行（在一般情况下是不可能的）。预emption版本，**最短剩余时间优先（SRTF）**，如果一个较短的工作到达，则中断正在运行的工作。

- **轮转调度（RR）**：每个进程分配固定的时间量子（例如10毫秒），然后被抢占并移动到队列的末尾。公平且响应迅速，但时间量子很重要：太小会导致过度上下文切换，太大则退化为先到先服务。

- **优先调度**：每个进程都有一个优先级。优先级较高的进程首先运行。危险的是**饥饿**：低优先级的进程可能永远无法运行，因为高优先级的进程不断到达。**老化**解决了这个问题：一个进程的优先级随着等待时间的增加而增加。

- **多级反馈队列（MLFQ）**：多个具有不同优先级和时间量子的队列。新进程从最高优先级队列开始（短时间量子）。如果一个进程使用了其全部时间量子（CPU密集型），则被降级到较低优先级队列（长时间量子）。交互性任务自然地保留在高优先级队列中（它们在使用时间量子之前会阻塞I/O）。这适应工作负载而不需要预先知道作业类型。

- **完全公平调度器（CFS）**：Linux的调度器。它维护一个红黑树（平衡二叉搜索树），按“虚拟运行时间”对进程进行排序，即它们消耗了多少CPU时间。具有最小虚拟运行时间的进程下一次运行。这确保了随着时间的推移，每个进程都能得到其公平份额。CFS在每次调度决策中每$O(\log n)$执行一次。

## 内存管理

- 操作系统管理物理RAM，将其分配给进程并在不再需要时回收。

- **分页**（从文件2）将虚拟内存划分为固定大小的页面和物理内存中的帧。页表映射页面到帧。分页通过消除外部碎片（由于所有页面都是相同大小而浪费的空间）来消除外部碎片。

- **分页加载**在程序第一次访问时将页面加载到RAM中（而不是在进程启动时）。这节省了内存：一个代码量为1GB的程序在典型运行期间可能只使用50MB。其余部分从未被加载。

- 当内存满时，需要一个新页面，操作系统必须 **驱逐** 一个现有页面。页置换算法（LRU、FIFO、clock、从文件2）决定驱逐哪个页面。好的替换策略可以减少页故障；坏的替换策略会导致奔溃。

- **分段**将内存分割成不同大小的段（代码、数据、栈、堆），每个段都有自己的基址和长度。分段提供了逻辑组织，而分页则提供了物理管理。现代系统使用分段较少（主要用于保护）并依赖分页进行内存管理。

- 堆是动态分配内存的地方（在C中为`malloc`/`free`，在Java中为`new`，Python中隐式）。操作系统向进程提供大块的内存，然后由**内存分配器**（例如`glibc malloc`、`jemalloc`、`tcmalloc`）将这些大块分割成更小的分配。内存分配器的设计会影响性能：碎片浪费空间，线程之间的竞争浪费时间。

## 文件系统是计算机中用于存储和管理数据的结构。它们提供了一种组织和访问文件的方式，使得用户可以方便地创建、读取、修改和删除文件。常见的文件系统包括FAT（文件分配表）和NTFS（新式文件系统）。这些文件系统通常与磁盘驱动器或固态硬盘相关联，并且支持多种文件格式和权限控制机制。

- **文件系统**在持久存储（SSD、HDD）上组织数据，形成一个命名的文件和目录层次结构。

- **inode**（索引节点）存储文件元数据：大小、所有权、权限、时间戳以及指向磁盘数据块的指针。文件名存储在目录中，该目录将名称映射到inode编号。这种分离意味着一个文件可以有多个名称（硬链接），指向同一个inode。

- **FAT**（文件分配表）：一种简单的文件系统，用于USB驱动器和SD卡。它通过一个映射每个簇（块）到下一个簇的表格来形成链式列表。简单但不支持权限、日志记录或大文件。

- **ext4**: Linux的默认文件系统。使用直接、间接、双间接和三间接块指针来处理任何大小的文件。支持** extents**（连续的块范围）以提高大文件的效率。最大文件大小：16 TB，最大分区：1 EB。

- **日志记录**可以防止系统崩溃导致的数据损坏。在修改文件系统结构之前，更改会被写入一个**日志**（日志）。如果系统在操作中途崩溃，日志会在重启时重新播放以完成或撤销操作。如果没有日志记录，在写入过程中发生崩溃可能会留下文件系统处于不一致状态（文件数据块更新但其索引节点未更新，反之亦然）。

- **基于B树的文件系统**（如Btrfs、ZFS）使用B树（平衡搜索树）来组织数据和元数据，从而实现高效的查找、快照复制和内置的数据完整性校验。这些B树与数据库索引中使用的相同B树相同。

## 系统调用和内核模式

- **系统调用**是用户程序与操作系统内核之间的接口。当一个程序需要执行特权操作（如读取文件、分配内存、创建进程或发送网络数据包）时，它会发起系统调用。

- CPU有两种工作模式：
    - **用户模式**：受限。程序可以执行自己的代码并访问自己的内存，但不能直接访问硬件、其他进程的内存或操作系统数据结构。
    - **内核模式**：不受限。操作系统内核可以访问所有硬件和内存。系统调用是用户模式到内核模式之间的受控入口点。

- 当程序调用`read()`时，以下会发生：
    1. 程序将参数放入寄存器并触发**陷阱**（软件中断）。
    2. CPU切换到内核模式，并跳转到系统调用处理程序。
    3. 内核验证参数、执行I/O操作并将数据复制到用户缓冲区。
    4. 内核切换回用户模式并返回结果。

- 常见系统调用：`open`，`read`，`write`，`close`（文件），`fork`，`exec`，`wait`，`exit`（进程），`mmap`，`brk`（内存），`socket`，`bind`，`listen`，`accept`（网络）。

- **中断** 是硬件信号，强制 CPU 停止当前操作并运行中断处理程序（在内核中）。键盘按下、网络数据包到达或定时器滴答等都会生成中断。定时器中断尤其重要：它是操作系统允许 preemptive 多任务的关键（抢占式多任务）。

## 网络基础

- 网络栈是操作系统的一个子系统，它使机器之间能够通信。理解它解释了分布式训练如何同步梯度、模型服务如何处理请求以及为什么延迟重要。

![TCP/IP栈：应用层、传输层、网络层和链路层，每个都添加了头文件](../images/tcp_ip_layers.svg)


- **TCP/IP模型**将网络组织成层次结构，每个层次提供对上一层的抽象：

    - **链路层**：处理单个物理链接（以太网、Wi-Fi）之间的通信。涉及MAC地址和帧。
    - **网络层（IP）**：从源到目的地路由数据包，每台机器都有一个**IP地址**（例如，IPv4的192.168.1.1或IPv6的128位地址）。路由器基于目标IP地址逐跳转发数据包。
    - **传输层（TCP/UDP）**：提供应用程序之间的端到端通信。
    - **应用层**：直接使用的协议，如HTTP、DNS和gRPC。

- **TCP**（传输控制协议）提供可靠、有序的交付。它建立连接（三次握手：SYN、SYN-ACK、ACK），保证所有数据按顺序到达（使用序列号和确认），重新发送丢失的数据，并控制发送速率以避免网络过载（**拥塞控制**）。成本是延迟：三次握手增加了往返时间，重传增加了延迟。

- **UDP**（用户数据报协议）提供不可靠、无序的交付。没有握手、没有重传、没有顺序保证。比TCP低得多的延迟。用于速度更重要于可靠性的场景：视频流媒体、在线游戏、DNS查找。在ML中，某些梯度同步协议使用基于UDP的RDMA以更低的延迟

- **sockets**是操作系统API用于网络通信的接口。一个**socket**由（IP地址、端口号）标识。服务器创建一个socket，将其绑定到端口（例如80用于HTTP），监听连接并接受它们。客户端创建一个socket，并连接到服务器的地址：端口。数据通过socket读写，就像文件一样

- **DNS**（域名系统）将人类可读名称（google.com）翻译为IP地址（142.250.80.46）。它是一个分布式、层次数据库：你的机器向本地解析器询问，本地解析器向根服务器询问，然后委托给每个域的权威服务器

- **HTTP**（超文本传输协议）是Web的请求响应协议。客户端发送一个请求（方法+URL+头+可选体），服务器发送一个响应（状态码+头+体）。ML模型服务（例如TensorFlow Serving、Triton）将模型暴露为HTTP或gRPC端点

- **Latency vs bandwidth**：延迟是数据从源到目的地传输所需的时间（由物理距离和网络跳数决定）。带宽是数据速率（每秒字节数）。一个高带宽、高延迟的连接（卫星互联网）可以传输大量数据，但每个字节需要很长时间才能到达。对于分布式训练，**延迟**对同步屏障（所有GPU必须等待最慢的那个）很重要，而**带宽**对传输大型梯度张量（第6章）很重要

## 虚拟化和容器

- **虚拟化**在单个物理机上运行多个操作系统。一个**hypervisor**（VMware、KVM、Xen）创建**虚拟机（VMs）**，每个都有自己的虚拟CPU、内存、硬盘和网络接口。每个VM运行一个完整的OS（guest OS），它认为自己拥有专用硬件

- 虚拟机提供强大的隔离（一个虚拟机崩溃不会影响其他），灵活性（在同一台机器上运行Linux和Windows，迁移虚拟机到不同的物理主机）。成本是开销：每个虚拟机运行完整的操作系统内核，消耗内存和CPU用于与宿主机操作系统重复的操作。

![VMs在虚拟硬件上运行单独的guest OSes；容器共享主机内核，并且非常轻量级](../images/container_vs_vm.svg)


- 容器（Docker、Podman）提供了一个更轻量级的替代方案。而不是虚拟化整个硬件，容器共享主机OS内核，并使用内核功能来隔离进程：

    - **命名空间**隔离进程可以看见的内容：每个容器都有自己的进程树视图（PID命名空间）、网络接口（网络命名空间）、文件系统挂载点（挂载命名空间）和主机名（UTS命名空间）。容器内的进程无法看到其他容器中的进程。

    - **cgroups**（控制组）限制进程可以使用的资源：CPU时间、内存、磁盘I/O和网络带宽。容器不能消耗超过其cgroup允许的资源，从而防止一个容器饿死其他容器。

- 容器以毫秒级启动（无需操作系统引导），具有最小的开销（共享内核），并由一个 **Dockerfile** 定义，该文件指定基础镜像、依赖项和命令。这使得它们可重复：`docker build` 在任何地方都产生相同的环境。

- 对于机器学习，容器解决了“在我的机器上工作”问题。一个包含特定版本的 CUDA、cuDNN、PyTorch 和 Python 的容器镜像被打包。任何人都可以在任何机器上精确地重现这个环境。云训练平台（如 AWS SageMaker 和 GCP Vertex AI）在容器中运行训练作业。

- **Kubernetes** (K8s) 通过调度容器到集群中的机器、重启失败的容器、根据负载进行缩放和管理容器之间的网络来 orchestrate容器。大规模的 ML 推送（数以千计的模型副本处理数百万个请求）在 Kubernetes 上运行。

## 安全基础

- 操作系统通过多种机制确保安全：

- **权限**：每个文件都有一个所有者、一组和权限位（读写执行对所有者、组和其他用户）。进程以启动它的用户身份运行，并且只能访问那些允许的权限位。**root**用户（UID 0）绕过所有权限检查，因此以root身份运行非常危险。

- **特权分离**：进程以最少需要的权限运行。一个Web服务器不需要root权限；它应该以一个只能读取Web文件并绑定到端口80的受限用户运行。如果服务器被攻破，攻击者的访问范围仅限于受限用户可以做的事情。

- **沙箱化**: 限制进程在文件权限之外可以执行的操作。**seccomp**（Linux）限制了进程可以调用的系统调用。**AppArmor**和**SELinux**定义了强制访问控制策略。容器结合命名空间、cgroups和seccomp来实现多层次隔离。

- **地址空间布局随机化（ASLR）**：每次程序运行时，随机化栈、堆和库的内存位置。这使得攻击者更难利用内存损坏漏洞（缓冲区溢出），因为它们无法预测代码或数据在内存中的位置。

- 安全是系统级的问题：链条只有最薄弱环节强。一个服务于系统的模型需要安全的网络通信（TLS/HTTPS），经过身份验证的API访问（API密钥、OAuth），输入验证（防止恶意输入）和隔离执行（容器，最小权限）。

2. 模拟轮转调度。给定一组具有 burst 时间的进程列表，模拟调度并计算平均等待时间。
```python
def round_robin(processes, quantum=3):
    """Simulate round-robin scheduling.
    processes: list of (name, burst_time) tuples.
    """
    queue = [(name, burst, 0) for name, burst in processes]  # (name, remaining, wait)
    time = 0
    log = []

    while queue:
        name, remaining, waited = queue.pop(0)
        waited += (time - waited - (processes[[p[0] for p in processes].index(name)][1] - remaining))
        run_time = min(quantum, remaining)
        log.append(f"  t={time:3d}: {name} runs for {run_time} (remaining: {remaining - run_time})")
        time += run_time
        remaining -= run_time

        if remaining > 0:
            queue.append((name, remaining, time))
        else:
            log.append(f"  t={time:3d}: {name} DONE (turnaround: {time})")

    for line in log:
        print(line)

print("Round Robin (quantum=3):")
round_robin([("P1", 10), ("P2", 4), ("P3", 6)], quantum=3)
```

3. 模拟LRU页面替换。给定一个页面访问序列和固定数量的帧，计算页面故障次数。
```python
def lru_page_replacement(pages, n_frames):
    """Simulate LRU page replacement."""
    frames = []
    faults = 0

    for page in pages:
        if page in frames:
            frames.remove(page)
            frames.append(page)  # move to most recently used
            status = "HIT "
        else:
            faults += 1
            if len(frames) >= n_frames:
                evicted = frames.pop(0)  # remove least recently used
                status = f"MISS (evict {evicted})"
            else:
                status = "MISS (cold)"
            frames.append(page)
        print(f"  Page {page}: {status}  frames={frames}")

    print(f"\nTotal faults: {faults}/{len(pages)} ({faults/len(pages):.0%})")

print("LRU with 3 frames:")
lru_page_replacement([1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5], n_frames=3)
```
