# MCP 可靠性、取消与流量控制：练习指南

- 课程路径：`phases/13-tools-and-protocols/29-mcp-reliability-cancellation-and-flow-control`
- 可运行 Python 文件：`main.py`

## 练习目标

把 `main.py` 的五个可靠性组件读懂并能验证：`RequestCoordinator`（空闲/最大截止时间、单调进度、stdio 与 HTTP 两种取消信号、取消与完成的终态竞态）、`MutationLedger`（用文件型 SQLite 事务做幂等去重、拒绝同 key 配不同参数、返回防御性副本、重开后保留记录）、`DurableTaskService`（确认取消但在 worker 观察到前保持非终态）、`BoundedSseBuffer`（压力下合并或丢弃进度、绝不丢最终响应），以及恢复辅助函数（代理安全的 SSE header、重连与重新获取计划）。随后按上游练习新增 `reserve_inventory` 变更并验证幂等、并发与恢复语义。

## 建议步骤

1. **跑通演示：** 运行 `python3 main.py`，确认它运行中心竞态的两种顺序、在临时文件型账本中执行事务性去重变更、压满有界进度缓冲区，并展示持久化 Task 从“已确认取消”移动到“worker 观察到取消”。
2. **先做四种事件顺序的交互实验：** 启动 `A` 后取消再 `complete()`（取消胜出，抑制最终响应）；启动 `B` 后完成再交付取消（保留响应，忽略迟到取消）；启动 `C` 在每个空闲截止时间前发进度再越过最大截止时间（进度可重置空闲、不可重置最大）；通过 Streamable HTTP 启动 `D` 并关闭响应流，再把 `D` 改为 stdio 观察取消信号如何变化。为每个场景记录终态、是否有最终响应、放上线的取消信号、客户端应忽略哪个事件。
3. **幂等键绑定（实践实验 1–3）：** 让 `reserve_inventory` 的 key 绑定 SKU、数量、租户和操作名；相同 key 加相同参数的重试返回首次预留；改变数量的重试在不产生新预留的情况下失败。
4. **恢复与安全（实践实验 4–6）：** 已提交但丢失响应的执行可按 key 对账；结果不记录任何秘密或支付数据；客户端未提供 key 时禁用自动重试。
5. **订阅中断与并发竞态（实践实验 7、8）：** 模拟订阅断开，决定下一步前先重新获取库存记录；在栅栏处启动两个账本连接并发提交同一 key，断言只提交了一次预留。
6. **防御性副本与跨重开对账（实践实验 9、10）：** 修改首次返回的预留对象，重放该 key 证明已存结果未变；关闭并重新打开账本文件后，按 key 对账该预留。若库存实际在另一服务，按上游要求说明该服务是否接受同一幂等键，或是否由事务性 outbox 把本地提交桥接到远端效果。

## 运行与验证

在工作区目录执行：

```bash
python3 main.py
python3 -m unittest discover -s tests
```

`python3 main.py` 打印竞态、去重、缓冲与任务状态的演示；`python3 -m unittest discover -s tests` 报告 23 项测试通过。上文命令已在本仓库对应 `code/` 目录实际运行确认：主程序正常退出，测试全部通过、无失败或跳过。

每新增一条 `reserve_inventory` 要求都应配一条测试；改动后重新运行两条命令，保持所有测试通过。
