## 规划状态与完成门禁

本文件使用以下状态，避免把“内容存在”误报成“产品已经可用”：

- **内容已审核**：版本化译文为 `reviewed`，来源路径、revision 和 SHA-256 与当前发布快照一致；它仍可能尚未进入阅读器。
- **中文理论可发布**：除人工审核外，还必须声明跟踪 `main`，通过来源对应与指纹检查，图片、公式、代码和 Mermaid 可正确呈现；理论 API 返回 `readKind: internal`，原文入口仍指向官方最新 `main`。
- **Phase 可学习**：该 Phase 已进入实践课程目录和规范路由；全部译文可发布；所有存在上游 `quiz.json` 的课程有中文测验；所有 Python 课程有工作区模板和练习指南；非 Python 例外按 Python-first 规则链接上游；理论关联已批准；API、桌面端和窄屏学习流程验收通过。
- **公开发布就绪**：满足相应内容或 Phase 门禁，并完成许可证与归属核对、SemVer 更新、`README.md`、发布说明、内容清单、项目进度以及应用 `package.json` / `package-lock.json` 版本同步。

实践状态流转为 `内容已审核 → 已审核，待接入 → 集成中 → 可学习 → 公开发布就绪`；理论状态流转为 `英文 fallback → draft → 维护者 reviewed → 中文全文可发布`。探索笔记保持可选，不阻断上述流转。

## C0：[P0] 理论卡内容与展示重构

当前英文 fallback 卡同时渲染“阅读最新英文原文”和“查看上游 main 原文”，但 `readUrl` 与 `sourceUrl` 实际指向同一个官方 `main` 地址。现有卡片内容也只有标题与一句摘要，不足以完成 `CONTEXT.md` 约定的“当前操作所需概念 + 展开后的关键推导、例子和练习”职责。

目标信息结构采用渐进式展示：折叠状态只保留“上下文理论”标识、概念标题、与当前段落的关系摘要和全文可用语言；展开状态依次提供“为什么现在需要”“核心直觉”“2–4 个关键点”“在本课中的具体应用或微型例子”“一个自检问题”和来源操作。卡片仍然连接完整理论正文，不在局部卡片中复制整篇理论。

`card` 元数据保留 `title`、`summary`，并使用内容契约确认的结构化字段 `context`、`intuition`、`keyPoints`、`application` 和 `checkQuestion`。字段名与必填规则已写入 `docs/content-schema.md`；应用 API、课程正文和学习助理证据使用同一组已批准内容，避免界面展示与助理上下文不一致。

截至 2026-08-31，C0 的实现、自动化门禁和本地 headless Chrome 验收已完成：当前可见的 223 张卡均具备扩展字段并绑定到中文课程标题锚点，英文 fallback 每张只提供一个规范化后的原文入口；API、助理证据、锚点、渲染、键盘、触摸、深浅色和 1440/1024/768/375 视口布局检查均已覆盖。`fast_worker` 逐卡确认 223 / 223 张卡的结构、实践锚点、理论来源和自检问题均通过，技术语义抽样未发现严重问题；维护者已确认该预审结果，且接受其明确的语义自动验证边界。C0 与 G0 因此作为 v0.14.0 完成。

## 风险、阻断项与明确延期

- **许可证治理**：G0 已完成分层许可证、ADR、第三方归属和 README/内容清单边界；后续新增内容仍须确认版权主体、贡献者授权和每项外部资产的适用条款。
- **理论卡迁移量**：当前可见的 235 张卡已完成扩展内容迁移；尚未接入的 76 张卡在 Phase 15–19 开放时必须通过同一内容门禁，不得继续展示旧式简单卡片。
- **人工审核吞吐**：79 篇理论的主要瓶颈是逐篇语义与视觉复核，不是生成草稿；进度只统计 `reviewed` 且指纹有效的文件。
- **上游漂移**：每个批次启动时先检查上游；已变化的源文件必须更新并重新审核，不能沿用旧 SHA-256 追求计划数字。
- **批次体量不均**：同样 13 篇理论的长度和图示复杂度可能差异很大；T2 以后在不破坏关联优先级的前提下按源文件体量平衡在制品。
- **课程集成回归**：开放新 Phase 会改变课程总数、默认/继续目标、导航和数据库状态路径；这些是每个 P 里程碑的强制回归面。
- **延期范围**：理论进度、理论笔记、理论自测、理论助理状态、Phase 2 以后的探索笔记、多设备同步、托管模型和联网搜索不进入本路线图；需要时另立里程碑并重新评估优先级。

## 维护方式

每完成并合并一个可复现里程碑，更新对应条目、日期、分子/分母、验证结果和下一项；草稿数量与未合并分支不计入完成度。若上游版本、内容审核状态或发布范围发生变化，先更新本清单和内容元数据，再推进实现。T/P 批次启动时冻结清单，结束时记录实际偏差；任何门禁未通过时保持原状态，不用“基本完成”替代可验证交付。
